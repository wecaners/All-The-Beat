# Feature Specification: 수강생 신규 곡 등록

## Overview

검색해서 없는 곡을 그 자리에서 곡명·아티스트로 만들고, 바로 그 곡의 추가요로 이어진다. 만든 곡은 운영자에게 검수 대기로 보인다(F-13, F-02 결과 없음, U-02c).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 올빗에 없는 곡을 만들어 추가요한다

- As: 올빗에 없는 곡을 찾은 수강생은
- I: 그 곡을 만들고 바로 추가요할 수 있다
- So: 막히지 않고 기다리는 사람에 들어가기 위해

#### Acceptance Scenarios

Scenario 1: **결과 없음에서 길 보기**

- Given: 검색어에 맞는 곡이 없을 때
- When: 결과 없음을 보면
- Then: 올빗에 없는 곡이라는 안내와 함께 이 곡을 만들어 추가요하는 길이 있다. 이번 주 핫한 곡이 있으면 "이런 곡은 어때요?"로 최대 3곡이 보인다

Scenario 2: **곡 만들기**

- Given: 로그인·약관 동의한 사용자가 결과 없음에서 길을 누르면
- When: 곡 이름(검색어로 미리 채워짐)과 아티스트를 쓰고 만들면
- Then: 곡이 만들어지고 그 곡 상세로 가며 추가요 시트가 바로 열린다. 곡 상세의 기다리는 수는 0이다

Scenario 3: **아티스트 제안**

- Given: 곡 만들기에서
- When: 아티스트를 치면
- Then: 이미 있는 아티스트 이름이 제안된다. 제안을 고르지 않고 다른 표기로 써도 같은 아티스트로 묶인다

Scenario 4: **이미 있는 곡**

- Given: 같은 아티스트(다른 표기 포함)에 같은 이름(다른 표기 포함)의 곡이 있을 때
- When: 만들면
- Then: 새로 만들지 않고 그 곡 상세로 가며 추가요 시트가 열린다

Scenario 5: **로그인하지 않았을 때**

- Given: 비로그인 사용자가 길을 누르면
- When: 로그인 안내에서 카카오로 로그인하면
- Then: 검색 화면으로 돌아와 곡 만들기가 다시 열려 있다(검색어 유지)

Scenario 6: **약관 동의 전일 때**

- Given: 로그인했지만 약관 동의 전인 사용자가 만들면
- When: 저장하려 하면
- Then: 저장되지 않고 동의 화면으로 간다. 동의하면 검색 화면으로 돌아와 곡 만들기가 다시 열려 있다

Scenario 7: **빈 입력**

- Given: 곡 이름이나 아티스트가 비었을 때
- When: 만들려 하면
- Then: 만들어지지 않고 무엇이 비었는지 안내한다

### User Story 2: 운영자가 쌓인 곡을 본다

- As: 운영자는
- I: 수강생이 만든 곡을 곡 목록에서 알아볼 수 있다
- So: 중복·오타를 검수하기 위해

#### Acceptance Scenarios

Scenario 8: **검수 대기 표시**

- Given: 수강생이 곡을 만들었을 때
- When: 운영자 곡 목록을 보면
- Then: 그 곡에 검수 대기 표시가 있다. 운영자가 만든 곡에는 없다

## Functional Requirements (mandatory)

- FR-1: MUST 검색 결과가 없으면 곡을 만들어 추가요하는 길을 보여준다. 두 번 이내 탭으로 추가요 시트에 닿는다(결과 없음 → 만들기 → 추가요 시트)
- FR-2: MUST 곡 이름은 검색어로 미리 채우고, 곡 이름·아티스트 모두 필수(각 100자)다
- FR-3: MUST 아티스트를 치면 기존 아티스트 이름을 제안한다. 다른 표기로 써도 기존 아티스트로 묶는다
- FR-4: MUST 같은 아티스트에 같은 이름의 곡(별칭 포함)이 있으면 만들지 않고 그 곡을 쓴다
- FR-5: MUST 만들기는 로그인·약관 동의한 사용자만 할 수 있다. 비로그인은 로그인 안내, 동의 전은 동의 화면으로 보내고, 끝나면 검색 화면의 곡 만들기로 돌아온다
- FR-6: MUST 만든 곡은 검수 대기 상태로 저장되고 누가 만들었는지 남는다. 바로 곡 상세·검색·추가요에 쓸 수 있다
- FR-7: MUST 만든 뒤 곡 상세로 가며 추가요 시트가 열려 있다
- FR-8: MUST 결과 없음에 이번 주 핫한 곡이 있으면 최대 3곡을 보여준다. 없으면 보이지 않는다
- FR-9: MUST 운영자 곡 목록에 검수 대기 곡을 표시한다
- FR-10: MUST YouTube 링크는 받지 않는다. 영상은 운영자가 정한다

## Constraints (mandatory)

- CON-1: MUST 운영자 검수 화면(필터·병합·승인), 오타 제안, 외부 API 검색은 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다(`reviewStatus`·`createdBy`가 이미 있다)
- CON-3: MUST 추가요 저장은 곡 상세의 기존 흐름을 그대로 쓴다. 새 곡 시트에서 추가요를 저장하지 않는다

## Success Criteria (mandatory)

- SC-1: 결과 없음에서 두 번 탭(만들기 → 만들기 완료)으로 추가요 시트가 열린 곡 상세에 닿는다
- SC-2: 만든 곡은 `pending` + 만든 사람이 기록되고, 운영자가 만든 곡은 `confirmed`로 남는다(되돌리는 트랜잭션 테스트)
- SC-3: 별칭이 같은 곡은 새로 만들어지지 않는다
- SC-4: 375px에서 가로로 넘치지 않는다
