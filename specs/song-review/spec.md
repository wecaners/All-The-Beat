# Feature Specification: 운영자 곡 검수와 병합

## Overview

운영자가 검수 대기 곡을 모아 보고 확인하거나 기존 곡으로 합치고, 아티스트 이름을 고치고 합친다(F-16, A-04).

## User Scenarios & Testing (mandatory)

### User Story 1: 운영자가 쌓인 곡을 검수한다

- As: 운영자는
- I: 수강생·강사가 만든 곡을 모아 보고 맞으면 확인할 수 있다
- So: 잘못된 곡이 그대로 남지 않게 하기 위해

#### Acceptance Scenarios

Scenario 1: **검수 대기 모아 보기**

- Given: 검수 대기 곡이 있을 때
- When: 운영 곡 목록에서 검수 대기만 보기를 고르면
- Then: 검수 대기 곡만 보이고, 각 곡에 누가 만들었는지(수강생·강사·운영자)와 만든 날이 보인다. 운영 홈에 검수 대기 수가 보인다

Scenario 2: **확인**

- Given: 검수 대기 곡 상세에서
- When: 확인하면
- Then: 검수 완료가 되고 목록의 검수 대기에서 빠진다

### User Story 2: 운영자가 중복 곡을 합친다

- As: 운영자는
- I: 중복 곡을 기존 곡으로 합칠 수 있다
- So: 추가요와 클래스가 한 곡에 모이게 하기 위해

#### Acceptance Scenarios

Scenario 3: **대상 고르기**

- Given: 곡 상세에서
- When: 합칠 대상을 검색해 고르면
- Then: 옮겨질 클래스·추가요 수가 보인다. 자기 자신, 이미 합쳐진 곡은 고를 수 없다

Scenario 4: **합치기**

- Given: 대상을 고르고 한 번 더 확인하면
- When: 합치면
- Then: 이 곡의 클래스·추가요·별칭이 대상 곡으로 옮겨지고, 이 곡의 이름이 대상의 별칭이 된다. 대상 곡 상세로 간다. 결과에 옮긴 수와 겹쳐서 남기지 않은 수가 보인다

Scenario 5: **겹칠 때**

- Given: 같은 사람이 두 곡 모두에 추가요했거나, 한 클래스가 두 곡을 모두 배우거나, 같은 별칭이 양쪽에 있을 때
- When: 합치면
- Then: 대상 곡 것을 남기고 이 곡 것은 버린다. 오류가 나지 않는다

Scenario 6: **합쳐진 뒤**

- Given: 합쳐진 곡이 있을 때
- When: 홈·검색·랭킹·목록·운영 목록을 보거나 옛 주소로 들어가면
- Then: 합쳐진 곡은 어디에도 나오지 않고, 옛 주소는 대상 곡으로 간다. 대상 곡의 기다리는 수와 클래스에 옮겨온 것이 더해져 있다

### User Story 3: 운영자가 아티스트를 정리한다

- As: 운영자는
- I: 아티스트 이름을 고치고 중복 아티스트를 합칠 수 있다
- So: 같은 아티스트의 곡이 흩어지지 않게 하기 위해

#### Acceptance Scenarios

Scenario 7: **이름 수정**

- Given: 아티스트 목록에서
- When: 대표 이름을 고치면
- Then: 곡 화면의 아티스트 이름이 바뀌고 새 이름으로도 검색된다

Scenario 8: **아티스트 합치기**

- Given: 아티스트 목록에서 대상을 고르고 확인하면
- When: 합치면
- Then: 이 아티스트의 곡·별칭이 대상으로 옮겨지고 이 아티스트 이름이 대상의 별칭이 된다. 곡 주소는 그대로다. 자기 자신·이미 합쳐진 아티스트는 고를 수 없다

## Functional Requirements (mandatory)

- FR-1: MUST 운영 곡 목록(`/admin/songs`)에 검수 대기 필터, 만든 사람 종류(수강생·강사·운영자), 만든 날을 보여준다. 운영 홈에 검수 대기 수와 그 목록으로 가는 길을 둔다
- FR-2: MUST 곡 상세에서 검수 상태를 보고 확인할 수 있다. 확인하면 검수 완료가 된다
- FR-3: MUST 곡 병합은 대상을 검색해 고르고, 옮겨질 클래스·추가요 수를 먼저 보여준 뒤 한 번 더 묻는다. 자기 자신·합쳐진 곡은 대상이 될 수 없다
- FR-4: MUST 병합은 한 트랜잭션으로 클래스 연결·추가요·별칭·이벤트를 대상으로 옮기고, 이 곡의 이름을 대상의 별칭으로 더하며, 이 곡을 "합쳐짐"으로 표시한다. 겹치는 것(같은 클래스·같은 사용자·같은 별칭)은 대상 것을 남긴다
- FR-5: MUST 합쳐진 곡은 수강생·운영 목록에 나오지 않고 옛 주소는 대상으로 간다(기존 동작 유지). 관련 곡 상세 캐시를 비운다
- FR-6: MUST 아티스트 목록에서 대표 이름을 고치면 이름과 대표 별칭이 함께 바뀐다
- FR-7: MUST 아티스트 병합은 곡·별칭을 대상으로 옮기고 이 아티스트 이름을 대상의 별칭으로 더하며 "합쳐짐"으로 표시한다. 곡 주소는 바꾸지 않는다. 자기 자신·합쳐진 아티스트는 대상이 될 수 없다
- FR-8: MUST 모든 동작은 운영자만 할 수 있다

## Constraints (mandatory)

- CON-1: MUST 대표 영상 자동 갱신, 병합 되돌리기, 수강생 화면 변경은 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다
- CON-3: MUST 운영 화면은 운영 화면 규칙(단순 폼·다크)을 따른다

## Success Criteria (mandatory)

- SC-1: 되돌리는 트랜잭션 테스트에서 A→B 병합 뒤 A의 클래스·추가요·별칭이 B에 있고, 겹친 것은 B 것만 남고, A는 `mergedIntoId = B`다
- SC-2: 병합된 곡의 slug 조회가 `merged`로 B를 가리키고, 검색·랭킹에 A가 나오지 않는다
- SC-3: 자기 자신·합쳐진 곡·순환 병합이 거절된다
- SC-4: 아티스트 이름 수정이 대표 별칭에 반영되고, 아티스트 병합 뒤 곡의 `artistId`가 B다
