# Feature Specification: 검색

## Overview

수강생은 곡명·아티스트명을 어떤 표기로 쳐도 원하는 곡을 찾아 곡 상세로 간다(F-02). 운영자는 클래스를 등록할 때 같은 검색으로 배우는 곡을 고른다(F-12·F-13). 로그인은 수강생 검색에 필요 없다.

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 곡을 찾는다

- As: 수강생은
- I: 곡명이나 아티스트명을 쳐서 곡을 찾을 수 있다
- So: 홈에 없는 곡도 바로 찾아가기 위해

#### Acceptance Scenarios

Scenario 1: **홈에서 검색 들어가기**

- Given: 홈에 있을 때
- When: 검색창을 누르면
- Then: 검색 화면으로 가고 바로 칠 수 있다

Scenario 2: **곡명으로 찾기**

- Given: 곡 "NEON"이 있을 때
- When: "neon"을 치면
- Then: 치는 동안 NEON이 결과에 나오고, 아티스트와 지금 상황(다가오는 클래스 수 또는 기다리는 사람 수)이 같이 보인다

Scenario 3: **별칭·표기 차이**

- Given: NEON에 다른 이름 "네온", 아티스트 A2O LITE에 다른 이름 "에이투오"가 있을 때
- When: "네온", "에이투오", "a2o lite", "A2OLITE" 중 하나를 치면
- Then: NEON이 나온다

Scenario 4: **아티스트로 찾기**

- Given: 아티스트에 곡이 여러 개일 때
- When: 아티스트 이름을 치면
- Then: 그 아티스트의 곡들이 나온다

Scenario 5: **곡 이름이 정확한 곡이 먼저**

- Given: 곡 이름이 검색어와 같은 곡과, 곡 이름에 검색어가 들어 있기만 한 곡이 있을 때
- When: 검색어를 치면
- Then: 이름이 같은 곡이 먼저 나온다

Scenario 6: **곡 상세로**

- Given: 결과가 보일 때
- When: 곡을 고르면
- Then: 그 곡의 상세로 간다. 뒤로 오면 같은 검색어와 결과가 보인다

Scenario 7: **없는 곡**

- Given: 맞는 곡이 없을 때
- When: 검색하면
- Then: "아직 올빗에 없는 곡이에요"와 다른 표기로 다시 쳐 보라는 안내를 본다

Scenario 8: **주소로 공유**

- Given: 검색 결과를 보고 있을 때
- When: 그 주소를 새로 열면
- Then: 같은 검색어와 결과가 보인다

### User Story 2: 운영자가 클래스의 곡을 고른다

- As: 운영자는
- I: 클래스를 등록할 때 곡을 검색해 고를 수 있다
- So: 곡이 많아도 빨리 고르기 위해

#### Acceptance Scenarios

Scenario 1: **한 곡 고르기**

- Given: 클래스 등록 화면일 때
- When: 곡을 쳐서 하나 고르면
- Then: 그 곡이 대표 곡으로 골라지고, 곡 검색 칸은 하나만 보인다

Scenario 2: **곡 더하기**

- Given: 한 곡을 고른 뒤
- When: "다른 곡도 배워요"로 곡을 더하면
- Then: 최대 세 곡까지 고를 수 있고, 세 곡이면 더 더할 수 없다

Scenario 3: **빼기**

- Given: 곡을 고른 뒤
- When: 빼면
- Then: 목록에서 빠지고, 첫 곡을 빼면 다음 곡이 대표 곡이 된다

Scenario 4: **없는 곡은 그 자리에서**

- Given: 찾는 곡이 없을 때
- When: 곡명과 아티스트를 넣어 새 곡으로 추가하면
- Then: 곡이 만들어지고 바로 골라진다. 같은 아티스트(다른 이름 포함)에 같은 곡명(다른 이름 포함)이 이미 있으면 새로 만들지 않고 그 곡이 골라진다

Scenario 5: **운영자가 아닐 때**

- Given: 운영자가 아닐 때
- When: 운영자 곡 찾기를 직접 부르면
- Then: 거절된다

## Functional Requirements (mandatory)

- FR-1: MUST 검색어를 정규화(대소문자·공백·특수문자 무시)해 곡 별칭과 아티스트 별칭(대표 이름 포함)에 포함되는지 찾는다
- FR-2: MUST 순서는 곡 이름 정확 > 아티스트 이름 정확 > 곡 이름 앞부분 > 아티스트 앞부분 > 곡 이름 포함 > 아티스트 포함, 같으면 다가오는 클래스가 많은 곡, 기다리는 사람이 많은 곡 순
- FR-3: MUST 결과는 최대 20곡, 병합된 곡·아티스트는 빼고 곡명·아티스트·썸네일(없으면 기본 이미지)·다가오는 공개 클래스 수·기다리는 수(최근 90일, 취소 제외)를 보여준다
- FR-4: MUST 검색어는 주소에 남고, 같은 주소는 같은 결과를 보여준다
- FR-5: MUST 치는 동안 잠깐 멈추면 결과가 바뀐다. 결과를 계산하는 동안 이전 결과는 그대로 두고 찾는 중임을 알린다
- FR-6: MUST 검색어가 비어 있으면 무엇을 치면 되는지 안내하고, 결과가 없으면 없다고 알린다
- FR-7: MUST 홈 위쪽에 검색 입구를 둔다
- FR-8: MUST 운영자 클래스 등록의 곡 선택은 같은 검색을 쓴다. 기본 한 곡, 최대 세 곡, 첫 곡이 대표, 빼기 가능, 찾는 곡이 없으면 곡명·아티스트로 그 자리에서 만든다(같은 곡이면 기존 곡)
- FR-9: MUST 운영자 곡 찾기는 운영자만 부를 수 있다

## Constraints (mandatory)

- CON-1: MUST 초성 검색, 강사 검색, 클래스 목록(F-03)·아티스트별 클래스 목록은 이번에 없다
- CON-2: MUST 없는 곡을 만들고 추가요하기(F-13)는 이번에 없다. 결과 없음에서 아직 없는 기능을 약속하지 않는다
- CON-3: MUST 스키마를 바꾸지 않는다
- CON-4: MUST 검색 결과는 서버가 계산한다. 브라우저는 DB에 직접 가지 않는다
- CON-5: MUST 하단 탭바는 이번에 없다

## Success Criteria (mandatory)

- SC-1: 곡 별칭으로 검색해도 같은 곡이 나온다 (F-02 수용 기준)
- SC-2: 홈에서 원하는 곡 상세까지 검색으로 두 번 고르면 닿는다 (검색창 → 곡)
- SC-3: 운영자가 곡이 수백 개여도 클래스의 곡을 이름을 쳐서 고른다

## OpenAPI Specification (optional)

외부 API는 없다. 페이지 `GET /search?q=`와 서버 액션 하나:

| 이름 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| 곡 찾기(운영자) | 검색어 | 곡 id·곡명·아티스트 최대 8개 | 운영자 |
