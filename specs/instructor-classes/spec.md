# Feature Specification: 강사 클래스 등록과 내 클래스

## Overview

승인된 강사가 클래스를 직접 올리고(즉시 공개), 내 클래스에서 상태를 바꾸고 앵콜에 답하며, 지난 클래스를 복사해 다시 연다(F-12, F-24 강사 응답, T-02·T-03).

## User Scenarios & Testing (mandatory)

### User Story 1: 강사가 클래스를 1분 안에 올린다

- As: 승인된 강사는
- I: 한 화면에서 클래스를 등록할 수 있다
- So: 인스타 스토리보다 빠르게 올빗에 알리기 위해

#### Acceptance Scenarios

Scenario 1: **입구**

- Given: 승인된 강사가 마이를 보면
- When: 강사 줄을 누르면
- Then: 내 클래스로 간다. 승인 전 강사나 비로그인은 신청 상태 화면 또는 마이로 간다

Scenario 2: **등록**

- Given: 등록 화면에서
- When: 곡, 날짜, 시작·종료, 장소, 가격, 난이도, 예약 링크를 넣고 등록하면
- Then: 바로 공개되고 그 클래스 상세로 간다. 이름을 비우면 "{첫 곡} 원데이 클래스"가 된다. 예약 링크 유형은 주소로 정해진다

Scenario 3: **잘못된 입력**

- Given: 등록 화면에서
- When: 과거 날짜, 시작보다 이른 종료, http(s)가 아닌 링크, 필수 누락, 곡 0개 또는 4개로 등록하면
- Then: 저장되지 않고 무엇이 문제인지 안내한다

Scenario 4: **곡 미리 선택**

- Given: 곡 상세에서 승인된 강사가 "이 곡으로 클래스 열기"를 누르면
- When: 등록 화면이 열리면
- Then: 그 곡이 골라져 있고 기다리는 사람 수가 보인다

Scenario 5: **장소**

- Given: 등록 화면에서
- When: 내 스튜디오 중 하나를 고르면
- Then: 권역이 그 장소로 채워진다(바꿀 수 있다). 없으면 새 장소를 검색해 추가하고 내 스튜디오에 저장된다. 가장 최근 쓴 장소가 미리 골라져 있다

### User Story 2: 강사가 내 클래스를 관리한다

- As: 강사는
- I: 내 클래스의 상태를 바꾸고 고치고 복사할 수 있다
- So: 외부 예약 상황을 올빗에 맞추기 위해

#### Acceptance Scenarios

Scenario 6: **목록**

- Given: 내 클래스가 있을 때
- When: 내 클래스를 열면
- Then: 다가오는 클래스와 지난 클래스가 나뉘고, 각각 날짜·시간·권역·가격·난이도·상태·예약 클릭 수·앵콜 수가 보인다. 다른 강사의 클래스는 없다

Scenario 7: **상태 바꾸기**

- Given: 다가오는 모집중 클래스에서
- When: 마감 임박 → 모집중 → 마감하기 → 마감 풀기를 하면
- Then: 각 상태가 되고 클래스 상세에도 그대로 보인다. 앵콜이 시작된 마감 클래스는 풀 수 없다

Scenario 8: **취소**

- Given: 다가오는 클래스에서
- When: 사유(인원 미달·개인 사정·기타)를 고르고 취소하면
- Then: 취소 상태가 되고 되돌릴 수 없다. 클래스 상세에 취소로 보인다

Scenario 9: **수정과 변경됨**

- Given: 종료 전 클래스에서
- When: 날짜·시간·장소 중 하나를 바꿔 저장하면
- Then: 클래스 상세에 24시간 동안 "변경됨"이 보인다. 가격만 바꾸면 보이지 않는다. 종료·취소된 클래스는 고칠 수 없다

Scenario 10: **복사**

- Given: 지난 클래스에서
- When: 복사해서 다시 열기를 누르면
- Then: 곡·장소·가격·링크·난이도·설명이 채워진 등록 화면이 열리고 날짜·시간은 비어 있다

### User Story 3: 강사가 앵콜에 답한다

- As: 강사는
- I: 기준을 넘은 앵콜에 답하고 앵콜 클래스를 열 수 있다
- So: 못 들어온 사람들을 다음 회차로 받기 위해

#### Acceptance Scenarios

Scenario 11: **응답**

- Given: 내 클래스에 전달된 앵콜이 있을 때
- When: 목록 맨 위의 카드에서 "검토할게요" 또는 "이번엔 어려워요"를 고르면
- Then: 앵콜 상태가 검토 중 또는 어려움이 되고 수강생 화면에도 그렇게 보인다. 다른 강사의 앵콜에는 답할 수 없다

Scenario 12: **앵콜 클래스 열기**

- Given: 검토 중인 앵콜에서
- When: 앵콜 클래스 열기를 누르면
- Then: 원 클래스 값이 채워진 등록 화면이 열리고, 등록하면 앵콜이 "열렸어요"가 된다

## Functional Requirements (mandatory)

- FR-1: MUST `/me/classes`·`/me/classes/new`·`/me/classes/{id}/edit`는 승인된 강사만. 비로그인은 마이로, 미승인은 신청 상태 화면으로
- FR-2: MUST 등록 입력·검증은 운영자 대리 등록과 같다(곡 1~3, 이름 30자, 오늘 이후 날짜, 30분 단위 시간, 종료 > 시작, 장소, 권역, 가격 ≥ 0, 난이도, http(s) 예약 링크, 정원, 설명 1,000자). 강사는 자기 자신으로만 등록한다
- FR-3: MUST 저장 즉시 공개되고 그 클래스 상세로 간다. 공개 조건은 기존과 같다(승인 강사)
- FR-4: MUST 곡은 검색해서 고르고 없으면 그 자리에서 만든다(검수 대기). `?song=`이면 미리 골라지고 그 곡의 기다리는 수를 보여준다
- FR-5: MUST 장소는 내 스튜디오(보관 안 한 것, 최근 사용 순)에서 고르거나 새로 검색해 저장한다. 권역은 장소로 채우고 바꿀 수 있다
- FR-6: MUST 내 클래스 목록은 다가오는(종료 전, 취소 아님)과 지난(종료·취소)으로 나누고, 날짜·시간·권역·가격·난이도·상태, 예약 링크 클릭 수, 앵콜 수를 보여준다. 내 것만
- FR-7: MUST 다가오는 클래스에서 마감 임박 표시·해제, 마감, 마감 풀기(앵콜 없을 때만), 취소(사유 3가지)를 할 수 있다. 취소·종료는 되돌리지 않는다
- FR-8: MUST 종료 전·취소 아닌 내 클래스를 고칠 수 있다. 시작·종료·장소가 바뀌면 변경 시각을 기록하고, 클래스 상세는 24시간 동안 "변경됨"을 보여준다
- FR-9: MUST 복사는 내 클래스의 곡·이름·장소·권역·가격·난이도·정원·링크·설명을 채우고 날짜·시간은 비운다
- FR-10: MUST 전달·검토 중 앵콜이 있는 내 클래스는 목록 맨 위에 답 카드로 보이고, 검토할게요/이번엔 어려워요로 답한다. 검토 중이면 앵콜 클래스 등록(원 클래스 값 채움)으로 이어진다
- FR-11: MUST 곡 상세에 승인된 강사만 보는 "이 곡으로 클래스 열기"를 둔다
- FR-12: MUST 모든 액션은 서버가 로그인·승인·소유를 다시 확인한다

## Constraints (mandatory)

- CON-1: MUST 썸네일·티저·스토리 공유·조회 수·"마감됐나요?" 배너·스튜디오 사진·시설 편집·랭킹 행의 클래스 열기는 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다(`scheduleChangedAt`·`cancelReason`이 이미 있다)
- CON-3: MUST 운영자 대리 등록·마감·앵콜 응답은 그대로 동작한다
- CON-4: MUST 등록·수정 화면에는 탭바가 없다

## Success Criteria (mandatory)

- SC-1: 강사 등록 → 공개 → 상세 이동, 운영자 등록과 같은 검증이 되돌리는 트랜잭션 테스트로 확인된다
- SC-2: 다른 강사의 클래스 수정·상태 변경·앵콜 응답이 거절된다
- SC-3: 일시·장소 수정 → `scheduleChangedAt` 기록, 가격 수정 → 기록 없음
- SC-4: 375px에서 가로로 넘치지 않는다
