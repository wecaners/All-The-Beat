# Feature Specification: 클래스 상세와 예약 링크 이동

## Overview

수강생이 클래스 하나의 정보를 확인하고 강사의 예약 채널로 넘어간다(F-05). 넘어간 순간을 클래스별로 한 번씩 센다(F-06). 예약·결제는 올빗이 하지 않는다(MVP 원칙 2).

## User Scenarios & Testing (mandatory)

### User Story 1: 클래스 정보를 본다

- As: 수강생은 (로그인하지 않아도)
- I: 클래스 하나의 일시·장소·가격·난이도·강사·설명과 지금 상태를 한 번에 볼 수 있다
- So: 이 클래스에 갈지 정하기 위해

#### Acceptance Scenarios

Scenario 1: **모집 중인 클래스 보기**

- Given: 공개된 모집 중 클래스가 있을 때
- When: 비로그인 수강생이 그 클래스 주소로 들어오면
- Then: 클래스 이름, 배우는 곡, 날짜·요일·시작~종료 시각(한국 시간), 스튜디오명·주소·권역, 가격, 난이도, 정원, 강사 활동명·인스타 아이디, 설명, "모집 중" 상태를 본다

Scenario 2: **곡이 여러 개인 클래스**

- Given: 곡 2개를 배우는 클래스일 때
- When: 수강생이 두 번째 곡을 고르면
- Then: 그 곡의 상세로 간다

Scenario 3: **무료·정원 없음·설명 없음**

- Given: 가격 0원, 정원과 설명을 넣지 않은 클래스일 때
- When: 수강생이 클래스를 보면
- Then: 가격은 "무료"로 보이고, 정원과 설명은 빈칸 없이 생략된다

Scenario 4: **클래스 이미지가 없을 때**

- Given: 강사가 올린 이미지가 없고 대표 곡에 안무 영상이 있을 때
- When: 수강생이 클래스를 보면
- Then: 대표 곡의 영상 썸네일을 YouTube 출처와 함께 본다. 대표 곡에도 영상이 없으면 이미지 없이 보인다

Scenario 5: **장소와 강사로 나가기**

- Given: 클래스를 보고 있을 때
- When: 주소를 고르면 / 강사를 고르면
- Then: 지도에서 그 주소를 찾은 결과가 열린다 / 강사의 인스타그램이 열린다

Scenario 6: **공개되지 않은 클래스**

- Given: 게재 동의가 없는 대리 등록 강사의 클래스, 또는 숨긴 클래스일 때
- When: 누구든 그 클래스 주소로 들어오면
- Then: 찾을 수 없다는 화면을 본다. 없는 번호로 들어와도 같다

Scenario 7: **공유 링크 미리보기**

- Given: 수강생이 클래스 주소를 메신저에 붙였을 때
- When: 미리보기가 만들어지면
- Then: 클래스 이름과 날짜·권역이 보인다

Scenario 8: **바깥에서 바로 들어온 사람**

- Given: 인스타 인앱 브라우저로 클래스에 바로 들어왔을 때
- When: 다른 곳을 둘러보고 싶으면
- Then: 뒤로 가기 기록이 없어도 홈으로 갈 수 있다

### User Story 2: 예약하러 간다

- As: 수강생은
- I: 모집 중인 클래스에서 강사의 예약 채널로 넘어갈 수 있다
- So: 강사가 받는 방식 그대로 예약하기 위해

#### Acceptance Scenarios

Scenario 1: **예약 채널 미리 알기**

- Given: 예약 링크 유형이 네이버 예약인 모집 중 클래스일 때
- When: 수강생이 예약하러 가기 전에
- Then: "예약은 강사님의 네이버 예약에서 진행돼요"처럼 어디로 가는지 미리 안다

Scenario 2: **예약 채널로 넘어가기**

- Given: 모집 중이거나 마감 임박인 공개 클래스일 때
- When: 수강생이 예약하러 가면
- Then: 그 클래스에 저장된 예약 링크가 새 창으로 열리고, 넘어간 1회가 기록된다

Scenario 3: **짧은 시간 안에 다시 누름**

- Given: 같은 사람(로그인했으면 같은 계정, 아니면 같은 브라우저)이 10분 전 안에 이 클래스로 넘어간 적이 있을 때
- When: 다시 예약하러 가면
- Then: 예약 채널은 다시 열리지만 기록은 늘지 않는다

Scenario 4: **10분이 지나서 다시 누름**

- Given: 같은 사람이 이 클래스로 넘어간 지 10분이 지났을 때
- When: 다시 예약하러 가면
- Then: 1회가 새로 기록된다

Scenario 5: **다른 사람은 따로 센다**

- Given: 서로 다른 두 브라우저일 때
- When: 둘 다 같은 클래스로 넘어가면
- Then: 2회가 기록된다

Scenario 6: **예약할 수 없는 클래스의 예약 주소로 직접 들어옴**

- Given: 마감·종료·취소된 클래스일 때
- When: 누군가 그 클래스의 예약 이동 주소를 직접 열면
- Then: 예약 채널로 가지 않고 그 클래스 상세로 돌아오며, 기록은 남지 않는다

Scenario 7: **공개되지 않은 클래스의 예약 주소**

- Given: 공개되지 않았거나 없는 클래스일 때
- When: 누군가 그 예약 이동 주소를 열면
- Then: 찾을 수 없다는 결과를 받고, 어디로도 이동하지 않으며, 기록은 남지 않는다

### User Story 3: 예약할 수 없는 클래스에서 다음 길을 찾는다

- As: 수강생은
- I: 마감·종료·취소된 클래스에서 왜 안 되는지 알고 다른 길로 갈 수 있다
- So: 막다른 길에서 그냥 떠나지 않기 위해

#### Acceptance Scenarios

Scenario 1: **마감된 클래스**

- Given: 강사가 마감한 클래스일 때
- When: 수강생이 클래스를 보면
- Then: "마감됐어요"를 보고 예약하러 갈 수 없으며, 같은 곡의 다른 클래스를 보러 갈 수 있다

Scenario 2: **끝난 클래스**

- Given: 종료 시각이 지난 클래스일 때 (저장된 상태가 아직 모집 중이어도)
- When: 수강생이 클래스를 보면
- Then: "끝난 클래스예요"를 보고 예약하러 갈 수 없으며, 같은 곡의 다른 클래스를 보러 갈 수 있다

Scenario 3: **취소된 클래스**

- Given: 강사가 취소한 클래스일 때
- When: 수강생이 클래스를 보면
- Then: "취소됐어요"를 보고 예약하러 갈 수 없으며, 같은 곡의 다른 클래스를 보러 가거나 그 곡에 추가요를 남기러 갈 수 있다

Scenario 4: **곡의 다른 클래스로**

- Given: 예약할 수 없는 클래스를 보고 있을 때
- When: 같은 곡의 다른 클래스를 보러 가면
- Then: 대표 곡의 상세로 가서 다가오는 클래스를 본다

## Functional Requirements (mandatory)

- FR-1: MUST 공개된 클래스는 로그인 없이 볼 수 있다. 공개 조건은 곡 상세의 다가오는 클래스와 같다 (숨김 아님, 승인된 강사, 대리 등록이면 게재 동의 있음)
- FR-2: MUST 공개되지 않았거나 없는 클래스는 상세와 예약 이동 모두 "찾을 수 없음"으로 응답하고, 존재 여부를 드러내지 않는다
- FR-3: MUST F-05의 표시 항목(클래스 이름, 곡 1~3개, 일시, 장소·권역, 가격, 난이도, 정원, 강사, 이미지, 설명, 상태)을 보여준다. 값이 없는 선택 항목은 생략한다
- FR-4: MUST 시각은 한국 시간으로 보여준다
- FR-5: MUST 상태는 취소 → 종료 시각이 지남 → 저장된 상태(마감·마감 임박·모집 중) 순서로 판단한다. 종료 시각이 지난 클래스는 저장된 상태와 관계없이 끝난 클래스다
- FR-6: MUST 모집 중·마감 임박 클래스만 예약하러 갈 수 있다. 예약하러 가기 전에 예약 채널 종류(네이버 예약·카카오 오픈채팅·인스타 DM·구글폼·그 밖)를 알려준다
- FR-7: MUST 예약 이동은 올빗의 예약 이동 주소를 거치고, 그 클래스에 저장된 예약 링크로만 보낸다. 요청에 담긴 다른 주소로는 보내지 않는다
- FR-8: MUST 예약 이동 1회마다 클래스, 시각, 로그인 사용자(있으면), 브라우저 식별값, 들어온 주소를 기록한다
- FR-9: MUST 같은 사람(로그인 사용자는 계정, 아니면 브라우저)·같은 클래스의 이동은 10분 안이면 한 번만 기록한다. 이동 자체는 매번 된다
- FR-10: MUST 예약할 수 없는 상태의 클래스로 예약 이동을 요청하면 기록 없이 클래스 상세로 돌려보낸다
- FR-11: MUST 예약 채널은 새 창으로 연다
- FR-12: MUST 곡을 고르면 그 곡의 상세로, 주소를 고르면 지도 검색으로, 강사를 고르면 강사의 인스타그램으로 간다
- FR-13: MUST 예약할 수 없는 클래스에서는 대표 곡의 상세(같은 곡 다른 클래스)로 갈 수 있다. 취소된 클래스는 대표 곡의 추가요 입력으로도 바로 갈 수 있다
- FR-14: MUST 공유 미리보기에 클래스 이름과 날짜·권역이 나온다
- FR-15: MUST 바깥에서 바로 들어와도 홈으로 가는 길이 있다

## Constraints (mandatory)

- CON-1: MUST 예약·결제·잔여석 확인을 하지 않는다. 정원은 숫자로만 보여주고 남은 자리를 말하지 않는다
- CON-2: MUST 앵콜(F-24), 강사 티저 영상(F-25), 넘어간 횟수를 보는 화면(F-18)은 이번 범위에 없다. 아직 없는 기능을 화면에서 약속하지 않는다 (MVP 원칙 6)
- CON-3: MUST 기록에 IP·기기 정보를 남기지 않는다. 누가 넘어갔는지는 다른 수강생에게 보이지 않는다
- CON-4: MUST 브라우저 식별값은 예약 이동 때만 만들고, 클래스를 보기만 한 사람에게는 만들지 않는다
- CON-5: MUST 이번 범위에 클래스 조회 수 기록, 클래스 이미지 올리기, 자동 종료 처리는 없다

## Success Criteria (mandatory)

- SC-1: 곡 상세의 클래스에서 예약 채널까지 두 번 고르면 닿는다 (클래스 → 예약하러 가기)
- SC-2: 곡 상세에 나온 클래스 중 상세가 "찾을 수 없음"인 것이 없다
- SC-3: 공개되지 않은 클래스는 상세·예약 이동 어디로도 드러나지 않는다
- SC-4: 같은 브라우저에서 10분 안에 여러 번 넘어가도 기록은 1건이고, 클래스별 넘어간 횟수를 셀 수 있다
- SC-5: 끝났거나 마감·취소된 클래스로는 예약 채널에 가지 않는다

## OpenAPI Specification (optional)

서버 액션은 없다. 페이지 하나와 브라우저가 여는 예약 이동 주소 하나가 있다.

```yaml
openapi: 3.0.3
info:
  title: 올빗 예약 링크 이동
  version: 1.0.0
  description: |
    클래스의 예약 링크로 보내기 전에 넘어간 1회를 기록한다 (F-06).
    로그인은 필요 없다.

paths:
  /go/{classId}:
    get:
      summary: 예약 채널로 이동
      description: |
        공개된 모집 중·마감 임박 클래스면 넘어간 1회를 기록하고(같은 사람·10분 안 중복 제외)
        그 클래스에 저장된 예약 링크로 보낸다.
      operationId: goToBooking
      tags:
        - Booking
      parameters:
        - name: classId
          in: path
          required: true
          description: 클래스 번호
          schema:
            type: integer
      responses:
        '302':
          description: |
            예약 가능 → 그 클래스의 예약 링크로.
            마감·종료·취소 → 클래스 상세(`/class/{classId}`)로, 기록 없음.
        '404':
          description: 없거나 공개되지 않은 클래스. 기록 없음
```
