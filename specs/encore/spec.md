# Feature Specification: 앵콜

## Overview

수강생은 마감됐거나 끝난 지 30일이 안 된 클래스에 앵콜을 남기고, 기준 인원까지 얼마나 남았는지와 강사의 응답을 클래스 상세에서 본다. 운영자는 기준에 닿은 앵콜을 강사에게 전하고, 강사의 답을 대신 남기며, 앵콜 클래스를 원 클래스와 연결해 등록한다(F-24). 운영자는 클래스를 마감으로 바꿀 수 있다(F-17 일부).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 앵콜을 남긴다

- As: 마감된 클래스를 놓친 수강생은
- I: 그 클래스에 앵콜을 남기고 진행 상황을 볼 수 있다
- So: 같은 강사의 같은 클래스가 다시 열리게 하기 위해

#### Acceptance Scenarios

Scenario 1: **앵콜할 수 있는 클래스**

- Given: 마감된 클래스, 또는 끝난 지 30일이 안 된 클래스일 때
- When: 클래스 상세를 열면
- Then: 앵콜을 남길 수 있고, 지금 앵콜한 사람 수와 기준까지 남은 수가 보인다

Scenario 2: **앵콜할 수 없는 클래스**

- Given: 모집 중·마감 임박·취소된 클래스일 때
- When: 클래스 상세를 열면
- Then: 앵콜을 남길 수 없다

Scenario 3: **로그인하지 않았을 때**

- Given: 로그인하지 않았을 때
- When: 앵콜을 누르면
- Then: 카카오 로그인 안내를 보고, 로그인하면 그 클래스로 돌아와 앵콜 입력이 바로 열린다

Scenario 4: **앵콜 남기기**

- Given: 로그인했고 아직 앵콜하지 않았을 때
- When: 희망 시간대와 한마디를 고르거나 비워 두고 앵콜하면
- Then: 인원이 1 오르고, 축하 순간을 보고, 내가 앵콜했다는 표시와 내가 고른 것이 보인다

Scenario 5: **두 번 앵콜하지 않는다**

- Given: 이미 앵콜했을 때
- When: 희망 시간대나 한마디를 바꿔 다시 저장하면
- Then: 내용만 바뀌고 인원은 그대로다

Scenario 6: **기준 인원 도달**

- Given: 기준까지 1명 남았을 때
- When: 앵콜을 남기면
- Then: 강사님께 전달됐다는 안내를 보고, 이후 누구에게나 "전달됐어요"가 보인다. 운영자 앵콜 목록에 그 클래스가 나타난다

Scenario 7: **앵콜 취소**

- Given: 앵콜했을 때
- When: 취소를 고르면
- Then: 한 번 더 묻고, 확인하면 인원에서 빠진다. 전달됐거나 검토 중이면 "취소하면 강사님이 보는 앵콜 인원에서 빠져요"라고 묻는다

Scenario 8: **상태는 뒤로 가지 않는다**

- Given: 전달됨 또는 검토 중일 때
- When: 취소로 인원이 기준 아래로 내려가면
- Then: 상태 문구는 그대로이고, 인원은 실제 현재 인원을 보여준다

Scenario 9: **검토 중은 강사가 답한 뒤에만**

- Given: 기준에 닿았지만 강사가 아직 답하지 않았을 때
- When: 클래스 상세를 보면
- Then: "검토 중"이 아니라 "전달됐어요"가 보인다

Scenario 10: **이번엔 어려워요·만료**

- Given: 강사가 이번엔 어렵다고 답했거나, 끝난 지 30일이 지났을 때
- When: 클래스 상세를 보면
- Then: 앵콜을 더 남길 수 없고, 그 이유와 함께 같은 곡의 다른 클래스·그 곡 추가요로 갈 수 있다

Scenario 11: **앵콜 클래스가 열렸을 때**

- Given: 앵콜 클래스가 등록됐을 때
- When: 원 클래스 상세를 보면
- Then: "앵콜 클래스가 열렸어요"와 함께 새 클래스로 갈 수 있다. 새 클래스 상세에는 앵콜 클래스라는 표시와 원 클래스로 가는 길이 있다

### User Story 2: 운영자가 강사에게 전하고 답을 남긴다

- As: 운영자는
- I: 기준에 닿은 앵콜을 보고 강사의 답을 대신 남길 수 있다
- So: 강사 화면과 알림이 없어도 앵콜이 강사에게 닿고 수강생이 결과를 알게 하기 위해

#### Acceptance Scenarios

Scenario 1: **응답이 필요한 앵콜 목록**

- Given: 기준에 닿았거나 검토 중인 앵콜이 있을 때
- When: 운영 앵콜 화면을 열면
- Then: 클래스·강사·인스타·인원·희망 시간대 분포·최근 한마디 5개·전달된 날짜가 보이고, 강사에게 전할 기대치 안내 문구가 보인다

Scenario 2: **검토할게요**

- Given: 전달됨 상태일 때
- When: 운영자가 검토할게요를 남기면
- Then: 수강생 화면에 "검토 중"이 보이고, 운영 화면에는 검토 시작 때 인원과 지금 인원이 함께 보인다

Scenario 3: **이번엔 어려워요**

- Given: 전달됨 또는 검토 중일 때
- When: 운영자가 이번엔 어려워요를 남기면
- Then: 응답 필요 목록에서 빠지고, 수강생 화면에 그렇게 보인다

Scenario 4: **앵콜 클래스 등록**

- Given: 전달됨 또는 검토 중일 때
- When: 운영자가 그 앵콜에서 앵콜 클래스 등록으로 가면
- Then: 원 클래스의 강사·곡·장소·가격·정원·난이도·예약 링크·설명이 채워져 있고, 날짜·시간만 넣어 등록하면 원 클래스와 연결되고 앵콜 상태가 오픈이 된다

Scenario 5: **모으는 중인 앵콜**

- Given: 기준에 닿지 않은 앵콜이 있을 때
- When: 운영 앵콜 화면을 열면
- Then: 클래스별 인원과 기준이 따로 보인다

Scenario 6: **운영자가 아닐 때**

- Given: 운영자가 아닐 때
- When: 운영 앵콜 화면이나 응답을 직접 부르면
- Then: 거절된다

### User Story 3: 운영자가 클래스를 마감한다

- As: 운영자는
- I: 강사가 마감됐다고 알려 온 클래스를 마감으로 바꿀 수 있다
- So: 수강생이 마감을 알고 앵콜을 남길 수 있게 하기 위해

#### Acceptance Scenarios

Scenario 1: **마감하기**

- Given: 모집 중이거나 마감 임박인 다가오는 클래스일 때
- When: 운영자가 마감하면
- Then: 클래스 상세에서 예약 대신 마감과 앵콜이 보인다

Scenario 2: **마감 풀기**

- Given: 마감한 클래스에 앵콜이 하나도 없을 때
- When: 운영자가 마감을 풀면
- Then: 다시 모집 중이 된다. 앵콜이 있었던 클래스는 풀 수 없다

## Functional Requirements (mandatory)

- FR-1: MUST 앵콜은 공개된 클래스 중 표시 상태가 마감 또는 종료이고, 종료 시각 + 30일 전이며, 앵콜 상태가 모으는 중·전달됨·검토 중일 때만 남길 수 있다
- FR-2: MUST 로그인한 사용자만 앵콜을 남기거나 취소한다. 서버가 로그인과 클래스 조건을 다시 확인한다
- FR-3: MUST 사용자 × 클래스 = 1건. 다시 저장하면 시간대·한마디만 바뀐다. 취소 후 다시 앵콜하면 새 앵콜로 센다
- FR-4: MUST 희망 시간대(평일 저녁/주말 낮/주말 저녁/상관없음, 기본 상관없음)와 한마디(최대 100자)는 선택이다. 한마디는 운영자(강사)만 본다
- FR-5: MUST 기준 인원은 정원이 있으면 정원의 30% 올림(최소 3명), 없으면 5명이며 그 클래스의 첫 앵콜 때 정해져 바뀌지 않는다
- FR-6: MUST 유효 앵콜 수가 기준에 닿는 순간 모으는 중 → 전달됨. 한 번만 일어난다
- FR-7: MUST 상태는 뒤로 가지 않는다. 취소로 인원이 줄어도 전달됨·검토 중은 유지된다
- FR-8: MUST 모으는 중·전달됨에서 종료 + 30일이 지나면 만료로 보인다. 검토 중은 만료되지 않는다
- FR-9: MUST 수강생 화면은 상태별로 실제로 일어난 일만 말한다: 모으는 중(현재 인원·남은 수·진행 정도), 전달됨, 검토 중(운영자가 검토할게요를 남긴 뒤에만), 앵콜 오픈(새 클래스로 가기), 어려워요·만료(같은 곡 다른 클래스·추가요로 안내)
- FR-10: MUST 인원은 누구에게나 숫자로만 보이고 누가 남겼는지는 보이지 않는다. 내 앵콜은 나에게만 보인다
- FR-11: MUST 앵콜 취소는 어느 상태에서든 되며, 확인을 한 번 더 받는다
- FR-12: MUST 첫 앵콜 순간에만 축하 움직임을 보여주고, 기준에 닿게 한 앵콜이면 전달됐다고 알린다
- FR-13: MUST 운영자 앵콜 화면은 응답이 필요한 앵콜(전달됨·검토 중, 만료 제외)과 모으는 중인 앵콜을 나눠 보여준다. 응답 필요 항목에는 인원(검토 중이면 검토 시작 때 인원과 지금 인원), 희망 시간대 분포, 최근 한마디 5개, 전달된 날짜·검토 시작 날짜, 강사 연락처(인스타), 기대치 안내 문구가 있다
- FR-14: MUST 검토할게요는 전달됨에서만, 이번엔 어려워요는 전달됨·검토 중에서만 남길 수 있다. 검토할게요를 남기면 그때의 인원을 저장한다
- FR-15: MUST 앵콜 클래스 등록은 원 클래스의 강사로 고정되고, 원 클래스의 곡·장소·가격·정원·난이도·예약 링크·설명을 미리 채운다. 원 앵콜이 전달됨·검토 중일 때만 연결되며, 등록과 상태 오픈은 함께 일어난다
- FR-16: MUST 앵콜 클래스 상세에는 앵콜 클래스 표시와 원 클래스 링크(원 클래스가 공개일 때), 원 클래스 상세에는 앵콜 클래스 링크(새 클래스가 공개일 때)가 있다
- FR-17: MUST 운영자는 다가오는 모집 중·마감 임박 클래스를 마감할 수 있고, 앵콜이 한 번도 없는 마감 클래스는 마감을 풀 수 있다
- FR-18: MUST 운영 화면과 응답은 운영자만 부를 수 있다

## Constraints (mandatory)

- CON-1: MUST 강사가 직접 쓰는 화면, 알림(F-20), 마이페이지 내 앵콜(F-10), 검토 중 14일 무응답 알림은 이번에 없다
- CON-2: MUST 우선 예약·인원 확정·예약금 같은 보장 못 하는 혜택을 어디에도 쓰지 않는다
- CON-3: MUST 스키마를 바꾸지 않는다(이미 있는 앵콜 테이블을 쓴다)
- CON-4: MUST 앵콜 인원은 저장하지 않고 유효 앵콜에서 센다(검토 시작 때 인원은 기준점이라 예외)
- CON-5: MUST 한마디와 누가 앵콜했는지는 수강생 화면·로그에 나오지 않는다

## Success Criteria (mandatory)

- SC-1: 기준 인원에 닿는 순간 운영 앵콜 화면에 그 클래스가 나타난다 (F-24 수용 기준)
- SC-2: 운영자가 검토할게요를 남기기 전에는 수강생 화면에 "검토 중"이 나오지 않는다
- SC-3: 앵콜 클래스를 등록하면 원 클래스에 앵콜한 사람 모두가 "앵콜 클래스가 열렸어요"를 본다
- SC-4: 같은 사용자가 같은 클래스에 두 번 앵콜해도 인원은 1만 오른다
- SC-5: 검토 중에 취소로 기준 아래로 내려가도 "검토 중"이 유지되고, 운영 화면에 검토 시작 때 인원과 지금 인원이 함께 보인다
- SC-6: 화면 어디에도 우선 예약처럼 보장 못 하는 혜택 문구가 없다
