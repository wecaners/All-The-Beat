# Feature Specification: 마이

## Overview

로그인한 수강생이 내가 남긴 추가요와 앵콜의 지금 상태를 한곳에서 보고, 열린 클래스로 바로 간다. 로그아웃할 수 있다. 로그인하지 않았으면 무엇을 할 수 있는지 먼저 보고 카카오로 시작한다(F-10, U-09).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 내 요청의 결과를 본다

- As: 추가요·앵콜을 남긴 수강생은
- I: 내 요청이 어떻게 됐는지 한곳에서 볼 수 있다
- So: 알림이 없어도 열린 클래스를 놓치지 않기 위해

#### Acceptance Scenarios

Scenario 1: **들어가기**

- Given: 홈에 있을 때
- When: 마이를 누르면
- Then: 마이로 간다

Scenario 2: **로그인하지 않았을 때**

- Given: 로그인하지 않았을 때
- When: 마이를 열면
- Then: 추가요·앵콜을 남길 수 있다는 안내와 둘러보기는 로그인 없이 된다는 안내, 카카오 로그인(카톡 복귀 안내 포함)을 본다. 로그인하면 마이로 돌아온다

Scenario 3: **내 추가요**

- Given: 기다리는 추가요와 클래스가 열린 추가요가 있을 때
- When: 마이를 열면
- Then: 열린 추가요가 맨 위에 눈에 띄게 있고, 각 항목에 곡·아티스트·내가 고른 권역·남긴 날짜가, 기다리는 항목에는 지금 기다리는 사람 수가 보인다. 취소한 추가요는 없다

Scenario 4: **추가요 항목 누르기**

- Given: 내 추가요가 보일 때
- When: 열린 추가요를 누르면 열린 클래스로, 기다리는 추가요를 누르면 곡 상세로 간다
- Then: 곡 상세에서 수정·취소할 수 있다

Scenario 5: **내 앵콜**

- Given: 상태가 다른 앵콜들이 있을 때
- When: 마이를 열면
- Then: 각 항목에 클래스·강사·날짜와 상태(모으는 중 지금 인원/기준, 전달됨, 검토 중, 앵콜 클래스 열림, 이번엔 어려워요, 기간 끝남)가 클래스 상세와 같게 보이고, 앵콜 클래스가 열린 항목이 맨 위에 있다. 취소한 앵콜은 없다

Scenario 6: **앵콜 항목 누르기**

- Given: 내 앵콜이 보일 때
- When: 앵콜 클래스가 열린 항목을 누르면 앵콜 클래스로, 나머지를 누르면 원 클래스 상세로 간다
- Then: 원 클래스 상세에서 수정·취소할 수 있다

Scenario 7: **아무것도 없을 때**

- Given: 추가요·앵콜이 없을 때
- When: 마이를 열면
- Then: 아직 없다는 안내와 곡을 찾으러 갈 길이 보인다

Scenario 8: **로그아웃**

- Given: 로그인했을 때
- When: 로그아웃하면
- Then: 홈으로 가고, 로그인하지 않은 상태가 된다

## Functional Requirements (mandatory)

- FR-1: MUST 홈 머리에 마이 입구를 둔다
- FR-2: MUST `/me`는 로그인 없이도 열리고, 비로그인이면 안내와 카카오 로그인(돌아올 곳 `/me`)을 보여준다
- FR-3: MUST 내 추가요는 취소되지 않은 것만, 열린 것 먼저, 그다음 최근에 남긴 순으로 보여준다
- FR-4: MUST 추가요 항목은 곡명·아티스트·영상 썸네일·권역(어디든 포함)·남긴 날짜를 보여주고, 기다리는 항목은 곡 상세와 같은 기준(최근 90일·취소 제외)의 기다리는 수를 보여준다
- FR-5: MUST 열린 추가요는 열린 클래스가 공개면 그 클래스로, 아니면 곡 상세로 간다. 기다리는 추가요는 곡 상세로 간다
- FR-6: MUST 내 앵콜은 취소되지 않았고 원 클래스가 공개인 것만, 앵콜 클래스가 열린 것 먼저, 그다음 최근에 남긴 순으로 보여준다
- FR-7: MUST 앵콜 항목의 상태·인원·기준은 클래스 상세와 같은 계산을 쓴다
- FR-8: MUST 앵콜 클래스가 열렸고 공개면 그 클래스로, 아니면 원 클래스로 간다
- FR-9: MUST 카카오 닉네임을 보여주고 로그아웃할 수 있다. 로그아웃하면 홈으로 간다
- FR-10: MUST 다른 사람의 추가요·앵콜은 보이지 않는다. 목록은 서버가 로그인 사용자로만 읽는다

## Constraints (mandatory)

- CON-1: MUST 회원 탈퇴, 약관 보기, 문의하기, 강사 신청·내 클래스, 알림 설정, 닉네임 바꾸기, 하단 탭바는 이번에 없다. 없는 기능의 입구를 두지 않는다
- CON-2: MUST 마이에서는 수정·취소하지 않는다
- CON-3: MUST 스키마를 바꾸지 않는다

## Success Criteria (mandatory)

- SC-1: 추가요한 곡의 클래스가 열리면 마이 맨 위에서 보이고 한 번 눌러 그 클래스로 간다
- SC-2: 앵콜 상태가 클래스 상세와 마이에서 같다
- SC-3: 로그아웃하면 마이가 로그인 안내로 바뀐다

## OpenAPI Specification (optional)
