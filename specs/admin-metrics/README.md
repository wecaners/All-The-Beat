# 운영자 지표

## Background

기획서 6절은 출시 뒤 8주 동안 "다음 단계로 갈지 판단할 최소 신호"를 정해 두었다. 클래스 30개, 자발적 등록 강사 3명, 예약 링크 클릭 50회, 요청 → 개설 1곡, 재방문 10명이다. 그런데 지금 운영 화면에는 할 일 목록(검수 대기 곡, 앵콜 응답 대기, 다가오는 클래스)만 있고, 이 숫자들을 한눈에 볼 곳이 없다. 예약 클릭은 클래스마다 따로 흩어져 있고, 재방문은 아예 기록되지 않는다.

운영자(창업자 1인)가 매주 "서비스가 일하고 있는가"를 판단하려면 DB를 직접 뒤지지 않고도 이 숫자들을 볼 수 있어야 한다(F-18).

## Goal

운영자가 운영 첫 화면에서 성공 지표 7개를 목표와 나란히 보고, 서비스가 일하고 있는지 판단한다.

## How it works

### 지표 보기 (운영자)

- 운영 화면에 들어가면 지표가 먼저 보인다. 지금 있는 할 일 목록(검수 대기 곡, 앵콜 응답 대기, 다가오는 클래스, 강사, 곡)은 그 아래에 그대로 둔다.
- 지표마다 지금 값과 기획서의 목표가 같이 보인다. 목표가 있는 지표는 목표에 닿았는지 알 수 있다.
- 숫자는 화면을 열 때마다 새로 센다. 지표 때문에 따로 저장하는 숫자는 없다.
- "이번 주"는 한국 시간 기준 월요일 0시부터다.

### 지표 7개

| 지표 | 보여주는 것 |
| --- | --- |
| 등록된 클래스 수 | 누적과 이번 주. 운영자 대리 등록과 강사 직접 등록을 나눠서 |
| 자발적 등록 강사 수 | 클래스를 직접 올린 적이 있는 강사 수 |
| 예약 링크 클릭 | 누적과 이번 주. 클릭이 많은 클래스 순 목록 |
| 추가요 수 | 지금 살아 있는 추가요 누적. 추가요가 많은 곡 순 목록 |
| 요청 → 개설 전환 | 추가요가 있던 곡 중, 첫 추가요 뒤에 클래스가 열린 곡 수와 그 곡들 |
| 앵콜 → 개설 전환 | 앵콜 기준 인원을 넘은 클래스 중 앵콜 클래스가 실제로 열린 비율 |
| 재방문 | 가입한 뒤 2주 안에 가입한 날이 아닌 다른 날 다시 들어온 사람 수 |

- 등록된 클래스 수에는 취소된 클래스와 숨긴 클래스를 넣지 않는다. 예약 링크 클릭은 숨긴 클래스 것도 센다(실제로 일어난 클릭이라서).
- 목록(클래스별 클릭, 곡별 추가요, 전환된 곡)에서 항목을 누르면 해당 운영 화면으로 간다.

### 재방문은 지금부터 센다

- 지금은 누가 언제 다시 들어왔는지 기록하지 않는다. 이 기능과 함께 로그인한 사용자가 서비스에 들어온 날짜를 하루에 한 번만 남기기 시작한다.
- 그래서 재방문 숫자는 기록을 시작한 날 이후 가입한 사람부터 정확하다. 화면에 기록을 시작한 날을 같이 보여준다.
- 비로그인 방문자는 세지 않는다. 기획서의 재방문 정의가 "가입자 중"이라서다.

### 이번에 하지 않는 것

- 차트, 기간 고르기, 내려받기(기획서: MVP는 표로 충분)
- 곡·클래스 조회 수, 검색어 순위, 유입 경로 (기록은 다음에 필요해질 때 정한다)
- 지표를 강사에게 보여주기 (강사는 내 클래스에서 자기 클래스의 예약 클릭만 본다. 지금처럼)
- 운영 DB 분리 전 테스트 데이터 걸러내기 (테스트 데이터 정리는 출시 전 할 일로 따로)
