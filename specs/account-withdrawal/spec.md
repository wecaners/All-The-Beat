# Feature Specification: 회원 탈퇴

## Overview

로그인한 사용자가 마이에서 직접 탈퇴하면 올빗에 남긴 개인 정보와 로그인 계정이 지워지고 카카오와의 연결이 끊긴다(F-09, F-10).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 탈퇴한다

- As: 로그인한 수강생은
- I: 마이에서 직접 탈퇴할 수 있다
- So: 더 쓰지 않는 서비스에 내 정보를 남기지 않기 위해

#### Acceptance Scenarios

Scenario 1: **확인을 받는다**

- Given: 로그인한 수강생이 마이에서
- When: 탈퇴를 고르면
- Then: 지워지는 것(회원 정보, 추가요 N건·앵콜 M건, 카카오 연결)과 되돌릴 수 없다는 안내를 보고, 그대로 두거나 탈퇴를 확정할 수 있다

Scenario 2: **그대로 두기**

- Given: 확인 안내에서
- When: 그대로 두기를 고르면
- Then: 아무것도 바뀌지 않는다

Scenario 3: **탈퇴 확정**

- Given: 추가요 2건·앵콜 1건·예약 클릭 1건·접속 기록이 있는 수강생이
- When: 탈퇴를 확정하면
- Then: 회원 정보·로그인 계정·추가요·앵콜·접속 기록이 지워지고, 곡·클래스의 숫자에서 빠진다. 예약 클릭은 숫자로만 남는다. 이 기기는 로그아웃되고 탈퇴했다는 안내를 받는다

Scenario 4: **다시 로그인**

- Given: 탈퇴한 사람이
- When: 같은 카카오 계정으로 다시 로그인하면
- Then: 새로 가입하는 것처럼 약관 동의부터 하고, 예전 추가요·앵콜은 없다

Scenario 5: **카카오 연결 끊기**

- Given: 카카오 연결 끊기를 쓸 수 있을 때
- When: 탈퇴를 확정하면
- Then: 카카오에서 올빗 연결이 끊긴다

Scenario 6: **카카오 연결 끊기 실패**

- Given: 카카오 연결 끊기가 실패할 때(키 없음, 카카오 오류)
- When: 탈퇴를 확정하면
- Then: 올빗의 정보는 그대로 지워지고 탈퇴 안내를 받는다. 실패는 서버 기록에 남는다

### User Story 2: 강사가 탈퇴한다

#### Acceptance Scenarios

Scenario 7: **강사 클래스 숨김**

- Given: 공개된 클래스가 있는 승인된 강사가
- When: 탈퇴를 확정하면(확인 안내에 클래스가 숨겨진다는 말이 있다)
- Then: 그 강사의 클래스가 수강생 화면에서 사라지고 강사 상태는 정지가 된다. 강사 정보와 클래스 기록은 운영 화면에 남는다

### User Story 3: 운영자는 탈퇴할 수 없다

#### Acceptance Scenarios

Scenario 8: **운영자 막기**

- Given: 운영자 계정이
- When: 탈퇴를 고르면
- Then: 운영자 계정은 탈퇴할 수 없다는 안내를 받고, 서버에 직접 요청해도 지워지지 않는다

### User Story 4: 비로그인

#### Acceptance Scenarios

Scenario 9: **비로그인**

- Given: 로그인하지 않은 사람에게는
- When: 마이를 열면
- Then: 탈퇴가 보이지 않고, 서버에 직접 요청해도 아무것도 지워지지 않는다

### User Story 5: 개인정보처리방침

#### Acceptance Scenarios

Scenario 10: **방침이 실제와 같다**

- Given: 개인정보처리방침을 열면
- When: 보관·탈퇴·쿠키 항목을 보면
- Then: 마이에서 직접 탈퇴한다는 것, 탈퇴 때 지우는 것과 남기는 것, 접속 날짜 기록과 그 쿠키가 실제 동작과 같게 적혀 있다

## Functional Requirements (mandatory)

- FR-1: MUST 마이(로그인 상태)에 탈퇴 입구가 있고, 확정 전에 지워지는 것과 되돌릴 수 없음을 한 번 더 묻는다
- FR-2: MUST 탈퇴는 로그인 계정과 회원 정보를 지우고, 추가요·앵콜·접속 날짜를 같이 지운다. 예약 클릭과 사용자가 만든 곡은 사용자 연결만 끊는다
- FR-3: MUST 강사면 같은 처리 안에서 그 강사의 모든 클래스를 숨기고 강사 상태를 정지로 바꾼다. 하나라도 실패하면 아무것도 바뀌지 않는다
- FR-4: MUST 운영자는 탈퇴할 수 없다
- FR-5: MUST 서버는 탈퇴 요청에서 로그인을 다시 확인하고, 로그인한 본인만 탈퇴시킨다(다른 사람 id를 받지 않는다)
- FR-6: MUST 정보를 지운 뒤 카카오 연결 끊기를 요청한다. 실패해도 탈퇴는 되돌리지 않고 서버 기록에 남긴다
- FR-7: MUST 탈퇴하면 이 기기는 로그아웃되고 탈퇴했다는 안내 화면으로 간다
- FR-8: MUST 개인정보처리방침의 보관·쿠키·내 정보 항목을 실제 동작에 맞춘다

## Constraints (mandatory)

- CON-1: MUST 카카오 어드민 키는 서버 전용 환경변수다. 브라우저로 나가지 않고 로그에 찍지 않는다
- CON-2: MUST 서버 로그에 닉네임·이메일을 남기지 않는다. 연결 끊기 실패 때는 카카오 회원번호만 남긴다
- CON-3: MUST 스키마를 바꾸지 않는다
- CON-4: MUST 탈퇴 사유, 유예·철회, 30일 뒤 자동 삭제, 운영자가 남을 탈퇴시키기는 이번에 없다
- CON-5: MUST 수강생 화면 규칙(design.md): 확인은 시트로, 밑줄 링크 대신 스티커 버튼, 탈퇴에 크게 터지는 움직임 없음

## Success Criteria (mandatory)

- SC-1: 되돌리는 트랜잭션 테스트에서 시나리오 3·7·8의 데이터 변화가 기대와 같다
- SC-2: 키가 없거나 카카오가 실패해도 탈퇴 함수가 정보를 지우고 성공을 돌려준다
- SC-3: `pnpm check`가 통과하고 개발 서버 로그에 prerender 경고가 없다

## 서버 액션 목록

| 이름 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
