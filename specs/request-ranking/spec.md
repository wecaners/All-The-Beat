# Feature Specification: 추가요 랭킹

## Overview

최근 30일 동안 사람들이 가장 기다린 곡을 순위로 보여준다. 전체와 권역별을 오가며 보고, 각 곡에서 바로 추가요하거나 곡 상세로 간다. 로그인 없이 누구나 본다(F-08, U-06).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 다른 사람들이 기다리는 곡을 본다

- As: 수강생은
- I: 사람들이 많이 기다리는 곡을 순위로 볼 수 있다
- So: 같이 기다리는 재미를 느끼고 내 추가요를 더하기 위해

#### Acceptance Scenarios

Scenario 1: **들어가기**

- Given: 홈에 추가요 TOP 5가 있을 때
- When: 더보기를 누르면
- Then: 추가요 랭킹으로 간다. 홈 TOP 5의 곡(3명 이상인 것)이 같은 순서로 앞에 있다

Scenario 2: **랭킹 보기**

- Given: 최근 30일 동안 추가요를 3명 이상 받은 곡이 있을 때
- When: 랭킹을 열면
- Then: 추가요가 많은 곡부터 최대 50곡이 보인다. 각 곡에 순위, 안무 영상 썸네일, 곡명·아티스트, 기다리는 사람 수, 이번 주(최근 7일)에 늘어난 수가 보인다. 누가 요청했는지는 보이지 않는다

Scenario 3: **순위 변화**

- Given: 지난주(7일 전 시점)의 랭킹과 지금 랭킹이 다를 때
- When: 랭킹을 보면
- Then: 순위가 오른 곡은 몇 계단 올랐는지, 내린 곡은 몇 계단 내렸는지, 지난주 랭킹에 없던 곡은 새로 들어왔다는 표시가 보인다. 같은 자리면 표시가 없다

Scenario 4: **클래스 여부**

- Given: 랭킹의 어떤 곡에는 다가오는 공개 클래스가 있고, 어떤 곡에는 없을 때
- When: 랭킹을 보면
- Then: 있는 곡은 "클래스 N개 열림", 없는 곡은 "아직 클래스 없음"이 보인다

Scenario 5: **곡 상세로**

- Given: 랭킹이 보일 때
- When: 곡을 누르면
- Then: 그 곡의 상세로 간다

Scenario 6: **랭킹이 비었을 때**

- Given: 3명 이상 기다리는 곡이 없을 때
- When: 랭킹을 열면
- Then: 아직 랭킹에 오른 곡이 없고 3명이 모이면 올라온다는 안내와, 곡을 찾으러 갈 길이 보인다

### User Story 2: 동네별로 본다

- As: 수강생(과 랭킹을 보는 강사)은
- I: 특정 권역을 희망한 추가요만으로 순위를 볼 수 있다
- So: 내 동네에서 기다리는 곡을 알기 위해

#### Acceptance Scenarios

Scenario 7: **권역 고르기**

- Given: 전체 랭킹을 볼 때
- When: 권역 하나를 고르면
- Then: 그 권역을 희망한 추가요만 센 랭킹이 보인다. 어디든 좋아요로 남긴 추가요는 들어가지 않는다. 순위 변화·이번 주 증가 수도 그 권역 기준이다

Scenario 8: **주소에 남기**

- Given: 권역을 골랐을 때
- When: 새로 고치거나 주소를 공유해 열면
- Then: 같은 권역 랭킹이 보인다. 전체로 돌아가면 주소에서 권역이 빠진다

Scenario 9: **모르는 권역**

- Given: 주소의 권역 값이 없거나 틀렸을 때
- When: 랭킹을 열면
- Then: 전체 랭킹이 보인다

### User Story 3: 랭킹에서 바로 추가요한다

- As: 수강생은
- I: 랭킹의 곡에 바로 추가요할 수 있다
- So: 곡 상세를 거치지 않고 한 번에 기다리는 사람에 들어가기 위해

#### Acceptance Scenarios

Scenario 10: **나도 추가요**

- Given: 랭킹이 보일 때
- When: 어떤 곡의 나도 추가요를 누르면
- Then: 그 곡의 상세로 가고 추가요 시트가 바로 열린다. 로그인·약관 동의가 필요하면 곡 상세와 같은 흐름을 거친다

Scenario 11: **랭킹에 없는 곡**

- Given: 기다리는 곡이 랭킹에 없을 때
- When: 맨 위의 검색 입구를 누르면
- Then: 검색으로 가서 곡을 찾아 추가요할 수 있다

## Functional Requirements (mandatory)

- FR-1: MUST 홈 추가요 TOP 5에 랭킹으로 가는 더보기를 둔다
- FR-2: MUST 랭킹은 로그인 없이 보인다
- FR-3: MUST 집계는 홈 TOP 5와 같다: 최근 30일 안에 만들어졌고 취소되지 않은 추가요를 곡별로 센다. 병합된 곡은 뺀다. 수가 같으면 최근에 요청이 들어온 곡이 앞이다
- FR-4: MUST 3명 미만인 곡은 보이지 않고, 최대 50곡까지 보인다
- FR-5: MUST 각 곡에 순위, 영상 썸네일(없으면 기본 배경), 곡명·아티스트, 기다리는 사람 수, 이번 주(최근 7일) 증가 수를 보여준다
- FR-6: MUST 순위 변화는 7일 전 시점의 랭킹을 같은 규칙(30일·취소 제외·3명 미만 제외·50곡)으로 계산해 견준다. 7일 전 시점에 취소되지 않았던 추가요를 센다
- FR-7: MUST 다가오는 공개 클래스(모집중·마감 임박, 시작 전)가 있으면 그 수를, 없으면 아직 없다고 보여준다. 이 수는 권역과 상관없다
- FR-8: MUST 권역을 고르면 그 권역을 희망한 추가요만 센다. 어디든 좋아요는 전체에만 들어간다
- FR-9: MUST 고른 권역은 주소(`?region=`)에 남는다. 값이 없거나 모르는 값이면 전체다
- FR-10: MUST 곡을 누르면 곡 상세로, 나도 추가요를 누르면 곡 상세의 추가요 시트가 바로 열린 상태로 간다
- FR-11: MUST 랭킹 맨 위에 검색으로 가는 입구를 둔다
- FR-12: MUST 비었을 때는 3명이 모이면 올라온다는 안내와 검색 입구를 보여준다
- FR-13: MUST 누가 요청했는지, 한마디는 보이지 않는다

## Constraints (mandatory)

- CON-1: MUST 강사 로그인 시의 "이 곡으로 클래스 열기"·분포·한마디 펼치기, 하단 탭바, 당겨서 새로고침, 순위가 바뀌는 움직임은 이번에 없다. 없는 기능의 입구를 두지 않는다
- CON-2: MUST 기간은 30일 고정이다. 기간을 고르는 기능은 없다
- CON-3: MUST 스키마를 바꾸지 않는다. 순위를 저장하지 않고 읽을 때 계산한다

## Success Criteria (mandatory)

- SC-1: 홈 TOP 5 중 3명 이상인 곡은 전체 랭킹 앞부분과 같은 순서다
- SC-2: 권역을 고른 랭킹의 수는 그 권역을 희망한 취소되지 않은 최근 30일 추가요 수와 같다
- SC-3: 지난주 랭킹에 없던 곡은 NEW, 있던 곡은 순위 차이만큼 ▲·▼가 맞다
- SC-4: 비로그인으로 열리고, 375px에서 가로로 넘치지 않는다
