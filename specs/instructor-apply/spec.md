# Feature Specification: 강사 신청과 승인

## Overview

수강생이 마이에서 강사를 신청하고, 운영자가 인스타 DM으로 보낸 코드로 본인을 확인하면, 운영자가 승인해 강사가 된다(F-11·F-14, T-01).

## User Scenarios & Testing (mandatory)

### User Story 1: 강사가 올빗에 신청한다

- As: 클래스를 직접 올리고 싶은 강사는
- I: 마이에서 강사를 신청하고 어디까지 됐는지 볼 수 있다
- So: 승인받아 클래스를 올리기 위해

#### Acceptance Scenarios

Scenario 1: **입구**

- Given: 로그인한 수강생이 강사 프로필이 없을 때
- When: 마이를 보면
- Then: 강사 신청 입구가 보인다. 비로그인이면 신청 화면은 마이로 보낸다

Scenario 2: **신청**

- Given: 신청 화면에서
- When: 활동명, 인스타 계정, 지역 하나 이상을 쓰고(소개는 선택) 신청하면
- Then: 승인 대기가 되고, 3단계 중 "신청 완료"가 끝나고 "인스타 본인 확인"이 지금 단계로 보인다. 마이에도 대기 중이라고 보인다

Scenario 3: **빈 입력·잘못된 계정**

- Given: 신청 화면에서
- When: 활동명·계정·지역 중 하나가 비거나 계정 형식이 틀리면
- Then: 신청되지 않고 무엇이 문제인지 안내한다. 소개가 50자를 넘어도 같다

Scenario 4: **이미 있는 계정**

- Given: 같은 인스타 계정의 강사가 이미 있을 때
- When: 신청하면
- Then: 신청되지 않고 이미 올빗에 있는 계정이라고 알린다. 운영자가 대신 등록한 계정이면 그렇다고 알린다

Scenario 5: **코드 입력**

- Given: 운영자가 코드를 발급했을 때
- When: 강사가 마이의 신청 상태에서 6자리를 넣으면
- Then: 맞으면 "확인됨"이 되고 "운영자 승인"이 지금 단계가 된다. 틀리면 틀렸다고, 24시간이 지났으면 만료됐으니 운영자에게 다시 받으라고 알린다. 아직 발급 전이면 운영자가 보내면 넣으라고만 알린다

Scenario 6: **승인·반려를 본다**

- Given: 운영자가 승인하거나 반려했을 때
- When: 마이나 신청 상태를 보면
- Then: 승인이면 강사로 승인됐다고 보인다. 반려면 사유가 보이고 내용을 고쳐 다시 신청할 수 있다. 다시 신청하면 승인 대기로 돌아간다

### User Story 2: 운영자가 확인하고 승인한다

- As: 운영자는
- I: 신청한 강사를 보고 코드를 발급·확인한 뒤 승인하거나 반려할 수 있다
- So: 본인이 맞는 강사만 클래스를 올리게 하기 위해

#### Acceptance Scenarios

Scenario 7: **목록**

- Given: 신청한 강사가 있을 때
- When: 운영 화면 강사 목록을 보면
- Then: 직접 신청한 강사는 상태(대기·확인됨·승인·반려)가 보이고, 대기·확인됨은 위로 모인다

Scenario 8: **코드 발급**

- Given: 강사 상세에서
- When: 코드 발급을 누르면
- Then: 6자리 코드가 한 번 보이고(DM으로 옮겨 적는다), 24시간 유효하다고 보인다. 다시 발급하면 이전 코드는 무효다

Scenario 9: **승인**

- Given: 강사 상세에서
- When: 승인하면
- Then: 승인 상태가 되고, 그 강사의 공개 조건이 충족된다(클래스가 생기면 수강생에게 보인다)

Scenario 10: **반려**

- Given: 강사 상세에서
- When: 사유를 적고 반려하면
- Then: 반려 상태와 사유가 저장되고 강사에게 보인다. 사유가 비면 반려되지 않는다

## Functional Requirements (mandatory)

- FR-1: MUST 마이에 강사 신청 입구(프로필 없음) 또는 신청 상태(있음)를 보여준다. 신청 화면은 로그인이 필요하고 비로그인은 마이로 보낸다
- FR-2: MUST 신청 입력은 활동명(30자)·인스타 계정(@·주소 허용, 소문자 정규화, 영문·숫자·.·_ 30자)·지역 하나 이상 필수, 한 줄 소개 50자 선택
- FR-3: MUST 사용자당 강사 프로필은 하나다. 신청은 대기 상태로 저장되고 운영자가 만든 것과 구분된다
- FR-4: MUST 같은 인스타 계정이 이미 있으면 신청하지 않고 알린다. 대리 등록 계정이면 그렇다고 알린다
- FR-5: MUST 신청 상태 화면은 신청 완료 → 인스타 본인 확인 → 운영자 승인 3단계와 지금 단계를 보여준다. 시간은 약속하지 않는다
- FR-6: MUST 운영자는 6자리 코드를 발급할 수 있다. 원문은 발급 때 한 번만 보이고, 서버는 해시와 24시간 만료만 저장한다. 재발급하면 이전 코드는 무효다
- FR-7: MUST 강사가 코드를 넣으면 맞을 때 확인됨이 된다. 틀림·만료·미발급을 구분해 알린다
- FR-8: MUST 운영자는 대기·확인됨 강사를 승인(승인 시각 기록)하거나 사유와 함께 반려할 수 있다. 승인은 확인 전에도 할 수 있다
- FR-9: MUST 반려된 강사는 내용을 고쳐 다시 신청할 수 있고, 다시 대기가 된다. 대기·확인됨·승인 상태에서는 고칠 수 없다
- FR-10: MUST 운영 강사 목록에 직접 신청한 강사의 상태가 보이고 대기·확인됨이 위로 온다
- FR-11: MUST 신청·코드·승인·반려는 서버가 로그인·권한·소유를 다시 확인한다. 다른 사람의 신청은 볼 수 없다

## Constraints (mandatory)

- CON-1: MUST 강사의 클래스 등록·내 클래스(F-12), 클레임(F-19), DM 자동 발송·알림(F-20), 프로필 사진 올리기, 정지(suspended)는 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다
- CON-3: MUST 신청 화면에는 탭바가 없다(04 IA 입력 화면)

## Success Criteria (mandatory)

- SC-1: 신청 → 코드 발급 → 입력 → 승인이 되돌리는 트랜잭션 테스트에서 상태 pending → verified → approved로 바뀌고, 승인된 강사는 `publiclyVisible` 조건을 만족한다
- SC-2: 같은 핸들 중복·빈 입력·틀린 코드·만료 코드가 각각 거절된다
- SC-3: 반려 → 재신청이 되고, 운영자가 만든 대리 강사는 영향이 없다
- SC-4: 375px에서 가로로 넘치지 않는다
