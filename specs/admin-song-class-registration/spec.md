# Feature Specification: 운영자 곡·클래스 등록

## Overview

운영자가 곡·아티스트를 등록하고, 동의받은 강사를 대신해 클래스를 등록해 수강생에게 공개한다. 출시 초기 공급을 운영자가 채우기 위한 기능이다 (MVP 원칙 4).

## User Scenarios & Testing (mandatory)

### User Story 1: 운영 기능은 운영자만 쓴다

- As: 운영자는
- I: 운영 화면에 들어가 곡·강사·클래스를 관리할 수 있다
- So: 수강생에게 보일 데이터를 채우기 위해

#### Acceptance Scenarios

Scenario 1: **운영자 접근**

- Given: 운영자로 지정된 계정으로 로그인했을 때
- When: 운영 화면 주소로 가면
- Then: 운영 화면이 열린다

Scenario 2: **일반 사용자·비로그인 차단**

- Given: 운영자가 아니거나 로그인하지 않았을 때
- When: 운영 화면 주소나 운영 기능을 직접 호출하면
- Then: 페이지를 찾을 수 없다는 결과를 받고, 아무 데이터도 바뀌지 않는다

### User Story 2: 곡과 아티스트를 등록한다

- As: 운영자는
- I: 곡명·아티스트·다른 이름·대표 영상으로 곡을 등록·수정할 수 있다
- So: 수강생이 그 곡을 찾고 추가요를 남길 수 있게 하기 위해

#### Acceptance Scenarios

Scenario 1: **새 아티스트와 곡 등록**

- Given: 아티스트 "A2O LITE"가 없을 때
- When: 곡명 "NEON", 아티스트 "A2O LITE", 다른 이름 "네온"으로 등록하면
- Then: 아티스트와 곡이 만들어지고, 곡 상세 주소로 열리며, "네온"으로도 찾을 수 있게 저장된다

Scenario 2: **대표 영상 지정**

- Given: 곡이 있을 때
- When: 퍼가기가 허용된 YouTube 링크와 영상 유형을 넣으면
- Then: 영상 제목·채널이 채워지고 곡 상세에 영상이 나온다

Scenario 3: **퍼가기 막힌 영상 거절**

- Given: 곡이 있을 때
- When: 퍼가기가 막혔거나 없는 영상의 링크를 넣으면
- Then: 저장되지 않고 이유를 안내받는다

Scenario 4: **중복 주소 거절**

- Given: 같은 slug의 곡이 이미 있을 때
- When: 같은 slug로 곡을 저장하면
- Then: 저장되지 않고 다른 주소를 쓰라는 안내를 받는다

### User Story 3: 대리 강사와 게재 동의

- As: 운영자는
- I: 강사 프로필을 만들고 게재 동의를 기록할 수 있다
- So: 동의받은 강사의 클래스만 공개하기 위해

#### Acceptance Scenarios

Scenario 1: **프로필 생성**

- Given: 인스타 아이디 "@Dance.Kim"인 강사가 없을 때
- When: 활동명·아이디·권역으로 프로필을 만들면
- Then: 아이디는 `dance.kim`으로 저장되고, 동의 전 상태로 보인다

Scenario 2: **동의 기록 후 공개**

- Given: 동의 기록 없는 강사의 클래스가 있을 때
- When: 동의 날짜와 방법을 기록하면
- Then: 그 강사의 다가오는 클래스가 곡 상세에 나타나고, 해당 곡의 대기 중 추가요가 "열렸어요"가 된다

### User Story 4: 클래스 대리 등록

- As: 운영자는
- I: 강사를 대신해 클래스를 등록할 수 있다
- So: 인스타에 공지된 클래스를 올빗에서 곡으로 찾게 하기 위해

#### Acceptance Scenarios

Scenario 1: **동의한 강사의 클래스 등록**

- Given: 동의 기록이 있는 강사와 곡 "NEON"이 있고, NEON에 대기 중 추가요가 있을 때
- When: 곡·일시·장소·가격·난이도·예약 링크를 넣어 등록하면
- Then: 클래스가 저장되어 NEON 곡 상세의 다가오는 클래스에 나타나고, NEON의 대기 중 추가요가 "열렸어요"가 된다

Scenario 2: **동의 없는 강사의 클래스**

- Given: 동의 기록이 없는 강사일 때
- When: 클래스를 등록하면
- Then: 저장은 되지만 수강생에게 보이지 않고, 추가요도 그대로 대기 중이다. 운영자는 아직 공개되지 않았다는 안내를 받는다

Scenario 3: **입력 검증**

- Given: 클래스를 등록할 때
- When: 지난 날짜, 시작보다 이른 종료, http(s)가 아닌 예약 링크, 곡 0개 또는 4개 이상을 넣으면
- Then: 저장되지 않고 무엇이 잘못됐는지 안내받는다

Scenario 4: **권역 추정과 장소 재사용**

- Given: 주소 "서울 마포구 양화로 100"을 넣을 때
- When: 권역을 따로 고르지 않으면
- Then: 권역이 홍대·합정으로 정해지고, 이 장소는 그 강사의 다음 등록 때 다시 고를 수 있다

## Functional Requirements (mandatory)

- FR-1: MUST 운영 화면과 운영 기능은 `role = admin`인 로그인 사용자만 쓸 수 있다. 아니면 404로 응답한다
- FR-2: MUST 곡은 곡명·아티스트·slug가 필수다. slug는 비우면 아티스트와 곡명으로 만든다
- FR-3: MUST 곡과 아티스트의 대표 이름은 다른 이름 목록에도 들어가고, 모든 다른 이름은 검색 정규화 값과 함께 저장한다
- FR-4: MUST 대표 영상은 YouTube 링크에서 영상 ID를 뽑고, 퍼가기 가능한 영상만 저장한다. 영상 유형은 필수다
- FR-5: MUST 운영자가 등록한 곡은 검수 완료 상태다
- FR-6: MUST 운영자가 곡을 고치면 그 곡의 상세 화면에 바로 반영된다
- FR-7: MUST 대리 강사 프로필은 활동명·인스타 아이디(소문자, @ 제외, 중복 불가)·권역 1개 이상이 필수다
- FR-8: MUST 게재 동의는 날짜와 방법 메모를 함께 기록한다
- FR-9: MUST 클래스 입력 검증은 F-12 규칙을 따른다 (곡 1~3, 이름 30자, 오늘 이후, 30분 단위, 종료 > 시작, 가격 ≥ 0, http(s) 링크, 설명 1,000자)
- FR-10: MUST 이름을 비우면 "{첫 곡명} 원데이 클래스"로 저장한다
- FR-11: MUST 예약 링크 유형은 주소로 추정하고, 운영자가 바꿀 수 있다
- FR-12: MUST 권역은 주소의 구로 추정하고, 못 찾으면 "기타 서울"이다. 운영자가 바꿀 수 있다
- FR-13: MUST 장소는 강사별로 저장되어 다음 등록 때 다시 고를 수 있다
- FR-14: MUST 클래스가 공개되는 순간(등록 시 동의가 있거나, 나중에 동의를 기록할 때) 그 클래스 곡들의 대기 중 추가요를 "열렸어요"로 바꾸고 그 클래스를 연결한다
- FR-15: SHOULD 운영 화면은 곡·강사·클래스 목록을 보여준다

## Constraints (mandatory)

- CON-1: MUST 운영자 지정은 화면이 아니라 DB 권한이 있는 스크립트로만 한다
- CON-2: MUST 수강생 화면에 "대신 등록" 표시를 하지 않는다
- CON-3: MUST 운영 화면은 검색 노출을 막는다
- CON-4: MUST 이번 범위에 곡 병합, 영상 자동 갱신, 클래스 숨김·강제 마감, 썸네일, 강사 승인·계정 연결은 없다
- CON-5: MUST YouTube 영상 검색에 API를 쓰지 않는다. 운영자가 링크를 붙여넣는다

## Success Criteria (mandatory)

- SC-1: 운영자가 새 곡(새 아티스트 포함)을 1분 안에 등록한다
- SC-2: 운영자가 동의받은 강사의 클래스 1개를 2분 안에 등록한다 (F-15 수용 기준)
- SC-3: 동의 기록이 없는 강사의 클래스는 수강생 화면 어디에도 나오지 않는다
- SC-4: 운영자가 아닌 사용자는 운영 기능으로 어떤 데이터도 바꿀 수 없다
