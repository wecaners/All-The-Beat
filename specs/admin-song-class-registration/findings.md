# Findings & Decisions

> **기술적 발견, 중요한 결정이 있을 때마다 이 파일을 즉시 업데이트하세요.**

## Requirements

- F-16: 운영자가 곡·아티스트를 등록·수정한다. 별칭 여러 개, 발매일, slug, 대표 영상(YouTube 링크 → 제목·채널·썸네일·임베드 가능 여부 자동, 운영자는 영상 유형만 고름, 임베드 막힌 영상은 등록 불가)
- F-15: 대리 강사 프로필(활동명·인스타 핸들·권역) 생성, 게재 동의 기록(날짜·방법 메모), 동의 기록 없이는 클래스 공개 불가, F-12와 같은 입력으로 클래스 대리 등록, "대신 등록" 표시 안 함
- F-12 입력 항목: 곡 1~3, 이름(최대 30자, 비우면 "{첫 곡명} 원데이 클래스"), 날짜(오늘 이후), 시작·종료(30분 단위), 장소(스튜디오명+주소, 이전 장소 재사용), 권역(주소로 추정·수정 가능), 가격, 난이도, 예약 링크(http/https, 유형 자동 추정), 정원, 설명 1,000자
- F-07: 클래스가 등록되면 같은 곡의 대기 중 추가요는 권역과 무관하게 "열렸어요"
- 04 IA: 운영자 화면은 `/admin/*`, 검색 노출 차단(noindex), 운영자만 접근

## Research Findings

### 코드베이스 구조

- 계층: `src/app` → `src/server` → `src/db` (ESLint로 강제)
- 로그인 사용자: `src/lib/auth/current-user.ts`의 `getCurrentUser()` (요청 시점, `connection()` 포함)
- 프로필·역할: `profiles.role`(`member`/`admin`) 컬럼이 이미 있다 (`src/db/schema/users.ts`)
- 공개 조건: `src/server/classes/index.ts`의 `publiclyVisible` — 숨김 아님 + 강사 `approved` + (대리 아님 또는 `consent_at` 있음)
- 권역 8개는 마이그레이션 `0003`으로 들어가 있다. `region_mappings`는 비어 있다
- 검색 정규화: `src/lib/normalize.ts`의 `normalizeAlias`
- 시드 스크립트 `scripts/seed-dev.mts`에 곡·아티스트·별칭 저장 방식(대표 이름도 별칭 1행, `is_primary`)이 있다

### 기존 패턴

- 서버 액션은 `src/app/<route>/actions.ts`에서 로그인 재확인 → zod 검증 → `src/server` 호출 → `refresh()`
- 폼 상태는 `useActionState`, 오류 문구는 사용자용과 서버 로그를 나눈다
- 곡 상세는 곡 정보를 `"use cache"` + `cacheTag(song:<slug>)`로 캐시한다 → 운영자가 곡을 고치면 `updateTag`가 필요하다

## Technical Decisions

| Decision | Rationale |
| -------- | --------- |
| 운영자 로그인은 별도 계정 대신 **카카오 로그인 + `profiles.role = 'admin'`** | IA는 "별도 로그인"이라 적었지만, 운영자가 둘뿐인 MVP에 비밀번호 계정을 따로 두면 관리할 비밀값만 늘어난다. 역할은 DB에만 있고 서버가 매번 확인한다 |
| 운영자가 아니면 `/admin`은 404 | "운영 기능이 있다는 것도 모르게" (README). 로그인 안내도 하지 않는다 |
| 운영자 지정은 스크립트로 (`pnpm admin:grant`) | 운영자를 지정하는 화면을 만들면 그 화면 자체가 공격 대상이 된다. DB 접속 권한이 있는 사람만 지정할 수 있게 한다 |
| 영상 정보는 YouTube **oEmbed**로 채운다 (API 키 없음) | 제목·채널·썸네일을 주고, 퍼가기가 막힌 영상은 401로 응답한다. Data API(`videos.list`)는 키 발급·쿼터 관리가 필요해 30일 갱신을 만들 때 도입한다 |
| 대리 강사는 만들 때 `approved` + `is_proxy = true` | 운영자가 직접 만든 프로필이라 승인 절차가 필요 없다. 공개 여부는 동의 기록만으로 갈린다 |
| 권역 추정은 시군구 단위 매핑부터 (`region_mappings` 시드) | 동 단위 매핑은 실제 클래스 30개를 모은 뒤 조정한다 (03 명세 2.1 [가정]). 주소 문자열에서 "서울 ○○구"를 찾아 매핑, 못 찾으면 "기타 서울" |
| 주소는 직접 입력 (다음 우편번호 검색은 나중에) | 운영자는 인스타 공지의 주소를 붙여넣는다. 강사 직접 등록(F-12) 때 주소 검색을 붙인다 |
| "열렸어요" 처리는 클래스가 **공개될 때** | 동의가 없어 숨겨진 클래스로 추가요를 닫으면 수강생은 열렸다는데 클래스를 못 본다(원칙 6). 동의를 나중에 기록하면 그때 처리한다 |
| 곡 slug는 자동 생성 + 수정 가능 | `아티스트-곡명`을 소문자·하이픈으로. 한글은 그대로 둔다 |

## Issues Encountered

### 1. 시군구 → 권역 매핑은 가정이다

**문제**:

권역 8개에 서울 25개 구를 어떻게 나눌지 정해진 기준이 없다.

**원인**:

권역 자체가 "사람들이 실제로 말하는 동네 묶음" 가정이다 (03 명세 2.1).

**해결**:

마포·서대문 → 홍대권, 강남·서초 → 강남권, 광진·성동 → 건대·성수, 송파·강동 → 잠실·송파, 종로·중구 → 종로·을지로, 관악·동작 → 신림·사당, 노원·강북·도봉 → 노원·수유, 나머지 → 기타 서울. 운영자가 클래스마다 바꿀 수 있다.

**결과**:

출시 전 실제 클래스 30개로 다시 확인한다.

### 2. 운영 DB와 개발 DB가 같다

**문제**:

지금 Vercel 운영 배포도 `allbeat-dev`를 쓴다. 운영자 지정·테스트 데이터가 운영 화면에도 보인다.

**원인**:

운영 DB를 아직 따로 만들지 않았다.

**해결**:

출시 전에 운영 DB를 분리한다. 그 전까지 테스트로 만든 강사·클래스는 이름에 "테스트"를 붙이고 동의 기록을 넣지 않아 수강생에게 보이지 않게 한다.

**결과**:

미정 (출시 전 작업)

### 3. 404가 HTTP 200으로 나간다

**문제**:

운영자가 아닐 때 `/admin`은 "찾을 수 없음" 화면을 보여주지만 HTTP 상태는 200이다.

**원인**:

운영자 확인이 쿠키를 읽어서 `<Suspense>` 안에서 돌고, 그때는 이미 응답 머리가 나간 뒤라 상태 코드를 바꿀 수 없다. 대신 Next.js가 noindex를 붙인다.

**해결**:

화면·데이터는 노출되지 않으므로 MVP에서는 둔다. 곡 상세의 없는 곡 주소와 같은 문제라 함께 다룬다.

**결과**:

보류

### 4. 퍼가기 막힌 영상은 아직 실제로 확인하지 못했다

**문제**:

oEmbed가 퍼가기 막힌 영상에 401을 준다는 동작을 실제 영상으로 확인하지 못했다.

**원인**:

퍼가기가 막힌 영상 ID를 아직 찾지 못했다.

**해결**:

운영자 화면에서 실제 막힌 영상을 만나면 확인하고 이 항목을 고친다.

**결과**:

미확인

### 5. 한글 slug 곡 상세가 "찾을 수 없음"이었다

**문제**:

운영자가 만든 `테스트가수-테스트곡` 곡 상세에서 제목(메타데이터)은 맞게 나오는데 본문은 "찾을 수 없음"이었다.

**원인**:

본문 렌더에서 받은 `params.slug`는 퍼센트 인코딩된 채(`%ED%85…`)였고, 메타데이터 쪽은 풀린 값이었다. 인코딩된 값으로 DB를 찾지 못했고, 그 "없음" 결과가 `"use cache"`에 캐시됐다.

**해결**:

`app/src/app/song/[slug]/page.tsx`에서 slug를 한 번 `decodeURIComponent`한 뒤 쓴다. 메타데이터와 본문이 같은 캐시 키를 쓰게 된다.

**결과**:

한글·영문 slug 곡 상세 모두 정상

### 6. 개발 서버의 instant 검증 경고

**문제**:

운영자가 아닌 사용자가 `/admin`을 열면 개발 서버 로그에 "Could not validate `instant`" 오류가 찍힌다.

**원인**:

개발 모드의 즉시 이동 검증이 페이지를 렌더하다 `notFound()`(운영자 아님)를 만난다. 레이아웃에 `instant = false`를 둬도 아래 페이지는 계속 검증된다.

**해결**:

개발 모드에서만 나는 로그이고 응답은 정상(찾을 수 없음)이라 그대로 둔다.

**결과**:

보류
