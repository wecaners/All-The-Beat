# Feature Specification: 운영자 클래스 관리

## Overview

운영자가 전체 클래스를 조건으로 찾아보고, 문제가 있는 클래스를 숨기거나 예약 링크를 고치거나 마감·종료·취소 처리한다(F-17, A-05).

## User Scenarios & Testing (mandatory)

### User Story 1: 운영자가 클래스를 찾아본다

- As: 운영자는
- I: 전체 클래스를 상태·강사·곡·권역·숨김으로 좁혀 볼 수 있다
- So: 문제가 있는 클래스를 빨리 찾기 위해

#### Acceptance Scenarios

Scenario 1: **전체 목록**

- Given: 다가오는·지난·취소·숨긴 클래스가 섞여 있을 때
- When: 운영 클래스 목록을 열면
- Then: 전부 보이고(최근 시작순), 줄마다 일시·이름·강사·권역·공개 여부·상태·예약 클릭·앵콜 수가 보인다

Scenario 2: **필터**

- Given: 목록에서
- When: 상태, 강사, 권역, 검색어(클래스 이름·곡·아티스트), 숨김만 보기를 고르면
- Then: 조건에 맞는 것만 보이고 조건은 주소에 남는다. 종료 시각이 지난 클래스는 "종료"로 걸린다

### User Story 2: 운영자가 클래스를 손본다

- As: 운영자는
- I: 숨기고, 링크를 고치고, 마감·종료·취소할 수 있다
- So: 잘못된 클래스가 수강생에게 보이지 않게 하기 위해

#### Acceptance Scenarios

Scenario 3: **상세**

- Given: 목록에서 클래스를 열면
- When: 상세를 보면
- Then: 일시·장소·권역·가격·난이도·정원·곡·설명·예약 링크·강사·누가 올렸는지(운영자/강사)·공개 여부·상태·클릭·앵콜이 보이고 수강생 화면으로 가는 링크가 있다

Scenario 4: **숨김**

- Given: 공개된 클래스에서
- When: 숨기면
- Then: 수강생 화면(홈·목록·곡 상세·클래스 상세)에서 사라지고, 강사의 내 클래스에는 남는다. 숨김을 풀면 다시 보인다

Scenario 5: **예약 링크 수정**

- Given: 상세에서
- When: 새 http(s) 주소를 저장하면
- Then: 링크와 유형이 바뀐다. http(s)가 아니면 저장되지 않는다

Scenario 6: **마감·풀기**

- Given: 모집중 클래스에서
- When: 마감하거나 풀면
- Then: 지금처럼 동작한다(앵콜이 시작된 마감은 풀 수 없다)

Scenario 7: **강제 종료**

- Given: 아직 시작 전인 클래스에서
- When: 한 번 더 확인하고 종료하면
- Then: 종료 상태가 되고 되돌릴 수 없다. 수강생 화면에 끝난 클래스로 보인다

Scenario 8: **취소**

- Given: 종료·취소되지 않은 클래스에서
- When: 사유(강사 요청·오류·기타)를 고르고 한 번 더 확인해 취소하면
- Then: 취소 상태와 사유가 저장되고 되돌릴 수 없다. 이미 종료·취소된 클래스는 취소할 수 없다

## Functional Requirements (mandatory)

- FR-1: MUST `/admin/classes`는 전체 클래스를 시작 시각 최근순으로 보여주고 상태·강사·권역·검색어·숨김 필터를 주소로 받는다. 상태는 화면 상태(종료 시각 지남 = 종료)로 거른다
- FR-2: MUST 줄마다 일시·이름·강사·권역·공개 여부·상태·예약 클릭 수·앵콜 수를 보여준다
- FR-3: MUST 상세는 클래스 정보 전체와 올린 주체, 공개 여부, 수강생 화면 링크를 보여준다
- FR-4: MUST 숨김·숨김 해제는 `isHidden`만 바꾼다. 상태와 강사 화면은 그대로다
- FR-5: MUST 예약 링크 수정은 http(s)만 받고 유형을 다시 정한다
- FR-6: MUST 강제 종료는 종료·취소 아닌 클래스를 종료로 만들고 되돌리지 않는다
- FR-7: MUST 운영자 취소는 사유(강사 요청·오류·기타)와 함께 종료·취소 아닌 클래스를 취소로 만들고 되돌리지 않는다
- FR-8: MUST 종료·취소는 한 번 더 묻는다. 모든 동작은 운영자만

## Constraints (mandatory)

- CON-1: MUST 신고 접수, 운영자의 내용 수정, 강사 알림은 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다
- CON-3: MUST 운영 화면 규칙(단순 폼·다크)

## Success Criteria (mandatory)

- SC-1: 되돌리는 트랜잭션 테스트에서 필터 5종이 맞는 집합을 주고, 숨김이 `getPublicClass`를 null로 만들며 풀면 돌아온다
- SC-2: 링크 수정이 유형을 재추정하고 http 아님을 거절한다
- SC-3: 종료·취소가 상태·사유를 남기고, 종료·취소된 클래스의 재처리가 거절된다
