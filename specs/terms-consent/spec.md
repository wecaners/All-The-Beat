# Feature Specification: 약관 동의

## Overview

처음 로그인한 사용자는 이용약관·개인정보 수집·이용에 동의한 뒤에 추가요·앵콜을 남길 수 있다. 동의는 한 번만 받고, 동의한 시각을 기록한다. 이용약관과 개인정보처리방침은 누구나 본다(F-09, U-08).

## User Scenarios & Testing (mandatory)

### User Story 1: 처음 로그인한 사용자가 동의한다

- As: 처음 카카오로 로그인한 수강생은
- I: 무엇에 동의하는지 보고 한 번에 동의할 수 있다
- So: 하려던 추가요·앵콜을 바로 이어서 하기 위해

#### Acceptance Scenarios

Scenario 1: **첫 로그인 뒤 동의 화면**

- Given: 아직 동의하지 않은 사용자가 곡 상세에서 추가요를 누르고 카카오 로그인을 마쳤을 때
- When: 올빗으로 돌아오면
- Then: 원래 화면 대신 동의 화면을 본다. 필수 둘(이용약관, 개인정보 수집·이용)과 선택 하나(소식 받기), 전체 동의가 있고 각 약관을 볼 수 있다

Scenario 2: **동의하고 이어가기**

- Given: 동의 화면에서
- When: 필수 둘에 동의하고 시작하면
- Then: 곡 상세로 돌아오고 추가요 시트가 자동으로 열린다. 동의 시각이 기록된다

Scenario 3: **필수를 빼고 시작**

- Given: 동의 화면에서
- When: 필수 중 하나라도 빠진 채 시작하면
- Then: 시작되지 않고 필수 동의가 필요하다는 안내를 본다

Scenario 4: **선택 동의**

- Given: 동의 화면에서
- When: 소식 받기를 고르거나 고르지 않고 시작하면
- Then: 고른 경우에만 선택 동의 시각이 기록된다. 어느 쪽이든 시작된다

Scenario 5: **다시 묻지 않는다**

- Given: 이미 동의한 사용자가
- When: 다시 로그인하거나 동의 화면 주소를 열면
- Then: 동의 화면 없이 원래 화면(또는 홈)으로 간다

Scenario 6: **동의 전에 요청하기**

- Given: 로그인했지만 동의하지 않은 사용자(동의 화면에서 벗어났거나 이 기능 전에 가입)가
- When: 추가요나 앵콜을 남기면
- Then: 저장되지 않고 동의 화면으로 가며, 동의하면 그 화면으로 돌아와 하려던 시트가 열린다

Scenario 7: **둘러보기는 그대로**

- Given: 동의하지 않은 사용자가
- When: 홈·검색·곡·클래스 상세를 보면
- Then: 막히지 않는다

### User Story 2: 누구나 약관을 본다

- As: 누구나
- I: 이용약관과 개인정보처리방침을 볼 수 있다
- So: 무엇을 수집하고 어떻게 쓰는지 알기 위해

#### Acceptance Scenarios

Scenario 1: **약관 화면**

- Given: 로그인하지 않았을 때
- When: 약관이나 개인정보처리방침 주소를 열면
- Then: 내용을 본다

Scenario 2: **마이에서**

- Given: 마이에서(로그인 전·후 모두)
- When: 약관·개인정보처리방침을 누르면
- Then: 그 화면으로 간다

## Functional Requirements (mandatory)

- FR-1: MUST 로그인 콜백은 동의 전 사용자를 원래 화면 대신 동의 화면으로 보내고, 원래 가려던 곳을 함께 넘긴다(상대 경로만)
- FR-2: MUST 동의 화면은 필수 둘·선택 하나·전체 동의와 각 약관 링크를 보여준다. 로그인하지 않았으면 홈으로, 이미 동의했으면 원래 가려던 곳으로 간다
- FR-3: MUST 동의 저장은 로그인 사용자만, 필수 둘이 모두 포함된 요청만 받고, 시각은 서버가 정한다. 선택 동의는 포함됐을 때만 기록한다
- FR-4: MUST 동의 여부는 이용약관·개인정보 동의 시각이 둘 다 있을 때만 참이다
- FR-5: MUST 추가요·앵콜 저장은 동의 전이면 저장하지 않고 동의가 필요하다고 알리며, 화면은 동의 화면(돌아올 곳은 그 화면과 하려던 시트)으로 보낸다
- FR-6: MUST 조회(홈·검색·곡·클래스·마이 보기)는 동의와 무관하게 된다
- FR-7: MUST `/terms`·`/privacy`는 로그인 없이 열리고, 마이(로그인 전·후)와 동의 화면에서 갈 수 있다
- FR-8: MUST 개인정보처리방침은 실제로 하는 일만 쓴다: 카카오에서 받는 항목, 추가요·앵콜 내용, 예약 클릭 쿠키(`ab_sid`, 1년), 서버 로그, 보관·삭제, 처리 위탁(Supabase·Vercel·카카오), 사용자 권리. 정해지지 않은 책임자·연락처는 빈칸으로 표시한다
- FR-9: MUST 마케팅 동의 문구는 "받을 수 있다"까지만 말하고 보내는 시기·내용을 약속하지 않는다

## Constraints (mandatory)

- CON-1: MUST 회원 탈퇴, 마케팅 동의 변경, 약관 개정 재동의, 문의하기는 이번에 없다
- CON-2: MUST 스키마를 바꾸지 않는다
- CON-3: MUST 약관 문서는 초안이며 법률 검토를 대신하지 않는다. 화면에 초안임을 표시한다
- CON-4: MUST 동의 시각 같은 증빙 값을 브라우저에서 받지 않는다

## Success Criteria (mandatory)

- SC-1: 첫 로그인 사용자는 동의 화면을 거쳐야 추가요·앵콜을 남길 수 있고, 동의 뒤 하려던 시트가 열린다
- SC-2: 동의한 사용자는 다시 로그인해도 동의 화면을 보지 않는다
- SC-3: 로그인 없이 `/terms`·`/privacy`가 열린다

## OpenAPI Specification (optional)

외부 API는 없다. 페이지와 서버 액션:

| 이름 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| `GET /welcome?next=` | 돌아갈 곳 | 동의 화면 또는 이동 | 로그인 사용자 |
| 동의 저장 | 필수 2 체크, 선택 1 체크, 돌아갈 곳 | 돌아갈 곳으로 이동 | 로그인 사용자 |
| `GET /terms`, `GET /privacy` | 없음 | 문서 | 누구나 |
