# Feature Specification: 하단 탭바

## Overview

수강생의 네 기본 화면(홈·클래스 목록·추가요 랭킹·마이) 아래에 탭바를 두어 어디서든 홈·찾기·추가요·마이로 한 번에 간다(04 IA 1절).

## User Scenarios & Testing (mandatory)

### User Story 1: 수강생이 기본 화면 사이를 오간다

- As: 수강생은
- I: 아래 탭으로 홈·찾기·추가요·마이에 바로 갈 수 있다
- So: 홈을 거치지 않고 원하는 곳으로 가기 위해

#### Acceptance Scenarios

Scenario 1: **탭바가 보이는 화면**

- Given: 홈, 클래스 목록, 추가요 랭킹, 마이 중 하나에 있을 때
- When: 화면을 보면
- Then: 아래에 홈·찾기·추가요·마이 네 탭이 있고 지금 화면의 탭이 켜져 있다. 클래스 목록에서는 찾기가 켜져 있다

Scenario 2: **탭 이동**

- Given: 탭바가 보일 때
- When: 홈·추가요·마이 탭을 누르면
- Then: 각각 홈·추가요 랭킹·마이로 간다. 마이는 비로그인이면 로그인 안내가 보인다

Scenario 3: **찾기 탭**

- Given: 탭바가 보일 때
- When: 찾기를 누르면
- Then: 검색으로 가고 검색 칸에 커서가 들어가 바로 칠 수 있다

Scenario 4: **누른 반응**

- Given: 탭바가 보일 때
- When: 다른 탭을 누르면
- Then: 켜진 표시가 그 탭으로 옮겨 가고 아이콘이 살짝 뛴다. 동작 줄이기를 켠 사용자에게는 바로 바뀐다. 이동을 기다리게 하지 않는다

Scenario 5: **내용이 길 때**

- Given: 목록이 화면보다 길 때
- When: 끝까지 내리면
- Then: 마지막 항목이 탭바에 가려지지 않고, 탭바는 계속 아래에 있다

Scenario 6: **탭바가 없는 화면**

- Given: 곡 상세, 클래스 상세, 검색, 약관 동의, 약관 문서, 운영 화면에 있을 때
- When: 화면을 보면
- Then: 탭바가 없다. 로고나 뒤로 가기로 나간다

Scenario 7: **홈 머리**

- Given: 홈에 있을 때
- When: 머리를 보면
- Then: 마이 버튼이 없고 로고만 있다. 마이는 탭으로 간다

## Functional Requirements (mandatory)

- FR-1: MUST 홈(`/`)·클래스 목록(`/classes`)·추가요 랭킹(`/requests`)·마이(`/me`)에 탭바를 둔다. 그 밖의 화면에는 두지 않는다
- FR-2: MUST 탭은 홈 `/`, 찾기 `/search`, 추가요 `/requests`, 마이 `/me` 순서다. 로그인이 필요 없다
- FR-3: MUST 켜진 탭은 현재 경로로 정한다. `/classes`는 찾기 탭이 켜진다
- FR-4: MUST 탭을 누르면 켜진 표시가 옮겨 가고 아이콘이 뛴다. 0.45초 안에 끝나고 이동을 막지 않는다. 동작 줄이기면 움직임 없이 바뀐다
- FR-5: MUST 탭바는 화면 아래에 고정되고 기기의 아래 안전 영역을 피한다. 탭바가 있는 화면의 내용 끝은 탭바에 가려지지 않는다
- FR-6: MUST 켜진 탭은 보조 기술에 현재 화면으로 알려진다
- FR-7: MUST 홈 머리의 마이 버튼을 없앤다

## Constraints (mandatory)

- CON-1: MUST 탭 숫자 표시, 강사용 탭, 당겨서 새로고침, 진동은 이번에 없다
- CON-2: MUST 스키마·서버 변경이 없다. 화면 부품과 네 화면의 붙임만이다

## Success Criteria (mandatory)

- SC-1: 네 화면에서 탭바가 보이고, 상세·검색·동의·약관·운영 화면에서는 보이지 않는다
- SC-2: 각 탭이 정해진 주소로 가고, 현재 경로에 맞는 탭이 켜져 있다
- SC-3: 375px에서 가로로 넘치지 않고, 긴 목록의 끝이 탭바에 가려지지 않는다
