## Research Findings

### 코드베이스 구조

- 강사별 장소 `instructor_places`(스튜디오명·주소·시군구·법정동·권역·마지막 사용)가 이미 있고, 운영자 클래스 등록이 최근 순으로 다시 고르게 한다(`src/server/admin/classes.ts`). 클래스는 장소 이름·주소를 스냅샷으로 저장하고 `placeId`로 연결한다
- 권역 추정 `guessRegion(address)`: 주소의 "○○구"로 `region_mappings`를 찾는다
- 강사 `instructor_profiles`: 활동명·인스타·상태·대리 여부·동의 시각·동의 메모뿐. 사진·소개·영상 칸이 없다
- YouTube: `parseYouTubeVideoId`, `lookupVideo`(퍼가기 막힘 거절)가 `src/server/youtube`에 있다 (곡 대표 영상에 사용 중)
- 사진 저장소(Supabase Storage)는 아직 쓰지 않는다. 버킷이 없다
- 환경변수에 카카오 키가 없다. 로그인용 카카오는 Supabase 콘솔에 설정돼 앱 환경변수를 쓰지 않는다
- 모든 테이블 RLS 켬 + 정책 0개 + anon·authenticated 권한 회수(마이그레이션 0002). 브라우저는 DB에 직접 못 간다

### 기존 패턴

- 운영 서버 액션은 첫 줄 `requireAdmin()`, 입력은 zod, 오류는 `AdminInputError`
- 화면 부품은 `design.md`의 표와 인터랙션 표를 따른다. 운영 화면은 흰 배경 단순 폼

## Technical Decisions

| Decision | Rationale |
| -------- | --------- |
| 스튜디오는 새 테이블을 만들지 않고 `instructor_places`를 넓힌다 (카카오 장소 id·장소 링크·위도·경도·시설·목록에서 뺀 시각) | 이미 강사별 재사용과 클래스 연결(`placeId`)이 있다. 이름만 "스튜디오"로 부른다 |
| 클래스는 지금처럼 이름·주소를 스냅샷으로 두고, 지도·시설·사진은 `placeId`로 스튜디오의 지금 값을 읽는다 | 공지한 장소가 바뀌면 안 되지만, 사진은 최신이 좋다 |
| 스튜디오는 지우지 않고 "목록에서 빼기"(`archived_at`) | 지난 클래스가 `placeId`로 가리키고 있다 |
| 카카오 로컬 API는 서버에서만 부른다 (REST 키는 서버 전용 Secret) | 키를 브라우저에 내리지 않는다. 브라우저 → 서버 → 외부 원칙 |
| 지도 미리보기는 카카오맵 JS SDK의 정적 지도(StaticMap)로, 장소 섹션이 화면에 들어올 때만 스크립트를 부른다. 좌표나 키가 없으면 미리보기를 숨긴다 | 움직이지 않는 지도라 스크롤을 뺏지 않고, 누르면 카카오맵이 열린다. 첫 화면 속도를 지킨다 |
| JavaScript 키는 `NEXT_PUBLIC_KAKAO_JS_KEY` | 지도 SDK는 브라우저에서 돌아 키가 공개된다. 카카오의 도메인 등록이 보호한다 (비밀값이 아니다) |
| 사진은 Supabase Storage 공개 버킷 `media`. 쓰기는 운영자만(RLS 정책 + `is_admin()` SECURITY DEFINER 함수) | 화면은 공개 주소로 읽는다. 브라우저 역할의 테이블 권한을 회수해 둬서, 정책 안의 운영자 확인은 정의자 권한 함수로 한다 |
| 사진 업로드는 서버 액션을 거친다: 브라우저가 1600px·480px 두 크기로 줄여 보내고, 서버가 로그인 세션으로 Storage에 올린 뒤 DB에 기록한다 | 브라우저가 DB·저장소에 직접 쓰지 않는다. 서버 액션 본문 1MB 안에 들어오게 줄인다. Supabase 이미지 변환(유료)을 쓰지 않는다 |
| 강사 소개 80자, 포트폴리오 YouTube 최대 2개(퍼가기 막힘 거절), 프로필 사진 1장 | 강사 입력 부담을 줄이고 상세 화면이 길어지지 않게 |
| 대리 등록 강사의 사진·영상·소개는 `media_consent`가 켜졌을 때만 공개. 직접 가입 강사는 본인이 넣은 것이니 바로 공개 | 게재 동의(F-15)는 클래스 공개 동의였다. 사진·영상까지 포함했는지 따로 기록한다 |
| 연습실 사진도 같은 동의(`media_consent`)를 따른다 | 대리 등록이면 연습실 사진도 강사에게서 받은 사진이다 |
| 강사 소개는 기존 `bio` 칸의 50자 제한을 그대로 쓴다 (spec의 80자 대신) | 이미 있는 칸·제약이다. 바꾸려면 제약 변경 마이그레이션이 필요하고, 짧을수록 상세가 길어지지 않는다 |
| 운영자가 고른 카카오 후보(좌표·장소 id·링크)는 서버가 형식·범위(한국 좌표, 카카오 장소 링크 형식)만 다시 확인한다 | 카카오 장소 API에 id로 다시 묻는 기능이 없다. 운영자만 부르는 기능이라 범위 확인으로 충분하다 |
| 카카오맵에 있는 스튜디오면 "카카오맵에서 사진·리뷰 보기"로 장소 페이지에 보낸다 | 지도 서비스의 사진을 가져오지 않는다(약관·저작권). 링크는 허용된다 |

## Issues Encountered

### 1. 카카오 API로 받은 좌표·장소 id를 저장해도 되는가

**문제**:

카카오 로컬 API 응답(좌표, 장소 id, 장소 링크)을 우리 DB에 저장해 계속 쓴다.

**원인**:

지도 서비스 약관은 데이터 저장·캐시를 제한하는 경우가 있다.

**해결**:

카카오 개발자 운영정책·로컬 API 약관을 확인해야 한다. 확인 전까지는 사용자가 스튜디오를 고를 때 한 번 받아 저장하는 최소 범위로 쓰고, 약관이 금지하면 좌표만 지우고 주소 링크로 되돌린다.

**결과**:

확인 필요 (사용자)

### 2. 카카오 키·마이그레이션 적용은 사용자 몫

**문제**:

카카오 키 입력과 공용 DB(운영과 같은 DB)에 마이그레이션 적용은 Claude가 하지 않는다.

**원인**:

`core-principles.md`: 비밀값 입력은 사용자, 운영 DB 쓰기는 확인 후.

**해결**:

사용자가 `.env.local`에 키 두 개를 넣고 카카오맵 사용 설정·JavaScript SDK 도메인(3100, 3101)을 등록했다. 마이그레이션 SQL은 사용자에게 보여주고 승인받아 적용했다. 운영(Vercel)에는 같은 두 키를 넣고 배포 도메인을 등록해야 한다.

**결과**:

해결 (운영 배포 설정은 머지 전 할 일)

### 3. 운영자 화면의 실제 저장은 확인하지 못했다

**문제**:

스튜디오 저장, 사진 올리기(Storage 정책), 강사 프로필 저장은 운영자 로그인 세션이 있어야 돈다.

**원인**:

로그인은 사용자 몫이고, 확인용 포트(3101)는 카카오 로그인 복귀 주소에 없다.

**해결**:

사용자가 운영자로 로그인한 화면에서 확인한다: 강사 페이지 → 스튜디오 찾기(장소 이름) → 고르기 → 시설·사진 1장 → 클래스 상세 반영, 강사 소개 저장(막힌 영상 거절 포함).

**결과**:

미확인

## Learnings

### 강사의 입력은 "한 번"으로 끝나야 한다 (2026-10-28)

사용자 피드백: 클래스마다 연습실 사진을 올리게 하면 강사가 불편하다. 정보는 클래스가 아니라 오래 가는 대상(스튜디오, 강사)에 붙이고, 처음 한 번만 넣게 한다. 입력을 줄이는 가장 좋은 방법은 이미 있는 데이터(카카오맵 장소)를 고르게 하는 것이다.

### 지도 SDK 오류는 화면을 깨지 않게 (2026-10-28)

확인 포트가 카카오에 등록되지 않았을 때 SDK가 401로 막혔다. 지도 미리보기는 실패하면 그리지 않도록 해 두어서, 사용자는 주소·카카오맵 버튼으로 같은 일을 할 수 있었다. 외부 서비스에 기대는 장식은 실패해도 핵심 동선(예약, 위치 찾기)을 막지 않게 만든다.
