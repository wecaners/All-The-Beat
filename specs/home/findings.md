## Requirements

- F-01 구성(위에서 아래): 검색창 → 이번 주 핫한 곡(오늘~7일 클래스가 있는 곡, 클래스 수 순 최대 10곡, 안무 영상 썸네일 + YouTube 출처, 곡명·아티스트·"클래스 N개", 영상 없으면 기본 그라데이션) → 다가오는 클래스(가장 가까운 10개) → 추가요 TOP 5(최근 30일, "N명이 기다려요" + [나도 추가요!], 더보기 → F-08)
- F-01 규칙: 데이터가 0개인 섹션은 숨긴다. 클래스 카드 공통 표시: 곡명·아티스트, 날짜(요일) 시간, 권역, 가격, 난이도, 상태 배지
- F-01 수용 기준: 비로그인 홈이 3초 안에(4G). 클래스가 하나도 없어도 추가요 섹션은 보인다
- 04 IA: 홈은 `/`, 탭바가 보이는 화면. 홈 → 곡 상세 → 클래스 상세 → 예약 = 3탭
- MVP 원칙 1(곡이 주인공), 5(비로그인으로 다 본다), 6(없는 기능은 약속하지 않는다)

## Research Findings

### 코드베이스 구조

- 지금 `/`(`app/src/app/page.tsx`)는 개발용 입구(곡 상세·로그인 검증 링크)다
- 곡 상세의 다가오는 클래스(`listUpcomingClassesForSong`)와 공개 조건(`publiclyVisible`)이 `app/src/server/classes`에 있다. 홈의 클래스·핫한 곡도 같은 조건을 써야 한다
- 추가요 집계(`getRequestSummary`)는 곡 하나 기준(최근 90일)이다. 곡 여러 개 순위 함수는 없다. 인덱스 `requests_song_created_idx (song_id, created_at) where status <> 'canceled'`가 있다
- 곡의 영상은 `videoEmbeddable === false`면 화면에서 숨긴다(`getSongBySlug`). 클래스 상세(`getPublicClass`)는 이 조건 없이 `ytVideoId`를 쓰고 있다 — 퍼가기가 막힌 영상이면 눌러도 재생되지 않는다 (Issues 1)
- 병합된 곡(`mergedIntoId`)은 추가요를 받지 않는다(`isRequestableSong`). 순위에서도 뺀다
- 검색(F-02), 클래스 목록(U-03), 추가요 랭킹(F-08), 마이(U-09)는 아직 없다

### 기존 패턴

- 요청마다 다른 데이터(다가오는 클래스, 추가요 수)는 `<Suspense>` 안에서 `await connection()` 뒤에 읽는다 (`app.md`)
- 화면 부품: `ClassTicket`(날짜 절취선 티켓), `StickerLabel`, `StarBurst`, `Tape`, `Logo`, `stickerButtonClass` (`_agent/rules/design.md`)
- 추가요 시트는 곡 상세 `?request=open`으로 바로 열린다
- 시안 round-2 홈: 핫한 곡은 가로로 넘기는 포토카드(196px, 번갈아 기울임, 테이프, 곡명 큰 글씨, 아티스트, 모서리 별 스티커 "클래스 N"), 다가오는 클래스는 티켓, 추가요 TOP은 색 동그라미 순위 + 썸네일 + 곡명·아티스트 + 숫자

## Technical Decisions

| Decision | Rationale |
| -------- | --------- |
| 검색창·하단 탭바·"더보기"는 이번에 만들지 않는다 | 갈 화면이 없다. MVP 원칙 6. 화면이 생길 때 붙인다 (README) |
| 세 묶음을 한 번에 읽고(`Promise.all`) 한 `<Suspense>` 안에서 그린다 | 셋 다 비었을 때 안내를 보여주려면 함께 알아야 한다. 쿼리는 병렬이라 늦어지지 않는다 |
| 세 묶음 모두 요청마다 읽는다 (`connection()`) | 다가오는 클래스·추가요 수는 요청마다 달라야 하는 데이터다 (`app.md`) |
| "이번 주"는 지금부터 7일(`starts_at > now()` and `< now() + 7일`), 모집 중·마감 임박만 센다 | F-01 "오늘~7일". 마감된 클래스로 곡을 띄우면 갈 클래스가 없다 |
| 다가오는 클래스 카드의 제목은 클래스 이름 대신 "곡명 · 아티스트" | F-01 카드 표시와 MVP 원칙 1(곡이 주인공). 클래스 이름은 상세에서 본다 |
| 추가요 TOP은 최근 30일, 취소 제외, 병합된 곡 제외, 같은 수면 최근 요청이 있는 곡 먼저 | F-01. 곡 상세의 90일과 다르다(홈은 "요즘"이 중요) |
| [나도 추가요!]는 곡 상세 `?request=open`으로 간다 | 추가요 입력·로그인 흐름이 곡 상세에 있다. 홈에서 따로 만들지 않는다 |
| 핫한 곡 카드는 새 부품 `SongCard`로 만든다 | 누르면 곡 상세로 가는 정지 포토카드. `VideoCard`는 누르면 재생이라 맞지 않는다. 랭킹·검색 결과에서도 쓴다 (`design.md`: 화면 안에 따로 만들지 않는다) |
| 영상 표시 조건(`videoEmbeddable !== false`)을 `src/server/songs`의 한 곳에 두고 홈·클래스 상세가 같이 쓴다 | 같은 규칙을 세 군데에 따로 쓰지 않는다. 클래스 상세의 누락도 같이 고친다 |
| 홈 세 묶음을 데이터만 받는 `HomeView`(`app/src/app/home-view.tsx`)로 분리 | 빈 묶음·여러 장·TOP 5를 DB를 바꾸지 않고 가짜 데이터로 확인하기 위해 (운영과 같은 DB) |
| 핫한 곡의 "클래스 N" 별 스티커는 모두 노랑(`butter`) | 핑크 별은 흰 외곽선 글씨라 11px에서 읽히지 않았다 |
| 추가요 TOP에 "LIVE" 스티커를 붙이지 않고 "Last 30 days" 라벨만 | 요청할 때 읽은 숫자라 실시간이 아니다 (MVP 원칙 6) |

## Issues Encountered

### 1. 클래스 상세가 퍼가기 막힌 영상을 보여줄 수 있다

**문제**:

`getPublicClass`가 `videoEmbeddable`을 보지 않아, 퍼가기가 막힌 영상이면 썸네일은 보이지만 눌러도 재생되지 않는다.

**원인**:

클래스 상세(`specs/class-detail`)를 만들 때 곡 상세의 숨김 조건을 옮기지 않았다.

**해결**:

영상 표시 조건을 `src/server/songs`의 `visibleVideoId`로 빼고 곡 상세·클래스 상세·홈이 같이 쓴다. 곡 상세·클래스 상세 썸네일이 그대로 나오는 것을 확인했다. 클래스 상세 기능의 버그라 커밋을 따로 나눈다.

### 2. 세 묶음이 모두 비면 홈이 비어 보인다

**문제**:

클래스도 추가요도 없으면(출시 직후) 빈 묶음 숨김 규칙 때문에 로고만 남는다.

**원인**:

F-01은 "클래스가 없어도 추가요 섹션은 보인다"까지만 정했다.

**해결**:

셋 다 비었을 때만 짧은 안내("곧 클래스가 채워져요" 류가 아니라, 지금 일어난 일만: "아직 열린 클래스가 없어요")를 보여준다. 약속 문구는 쓰지 않는다 (원칙 6).

### 3. 미리보기 탭에서 홈이 불러오는 중 화면에 멈췄다

**문제**:

브라우저 미리보기에서 홈이 뼈대(불러오는 중)에서 넘어가지 않았다. 서버는 묶음을 보냈고 숨은 영역에 들어 있었다.

**원인**:

미리보기 창이 숨겨져 있고 탭이 뒤에 있어 `requestAnimationFrame`이 돌지 않았다. React는 스트리밍된 내용을 애니메이션 프레임에 맞춰 바꿔 끼운다. 앱 문제가 아니라 확인 환경 문제다.

**해결**:

미리보기를 보이게 하고 탭을 앞으로 가져와 다시 불러왔다. 같은 확인에서 뼈대의 두 번째 카드가 375px 밖으로 나가는 것을 발견해 잘랐다.

## Learnings

### 입구는 갈 곳이 생길 때 만든다 (2026-10-28)

와이어프레임의 검색창·탭바·더보기는 완성된 서비스의 모습이다. 화면이 하나씩 생기는 지금 그대로 그리면 누를 때마다 막힌 길이 된다. 입구는 그 화면과 같은 커밋에서 붙인다.
