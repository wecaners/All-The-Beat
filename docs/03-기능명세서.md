## 1. 개요

### 1.1 한 문장
지금 유행하는 K-pop 곡의 오프라인 원데이 댄스 클래스를 **곡으로 찾고**, 없으면 **"추가요!"로 요청**하는 모바일 웹 서비스.

### 1.2 MVP 원칙 (기능을 판단할 때 기준)
1. **곡이 주인공이다.** 모든 탐색의 출발점은 곡(과 아티스트)이다.
2. **예약·결제는 하지 않는다.** "예약하기"는 강사의 기존 링크로 보낸다.
3. **강사는 하던 대로.** 등록은 1분, 입력 필드는 최소.
4. **초기 공급은 운영자가 채운다.** 운영자 대리 등록(콘시어지)이 1급 기능이다.
5. **비로그인으로 다 본다.** 로그인은 "추가요"와 강사 등록에만 필요하다.
6. **시스템이 보장할 수 있는 것만 약속한다.** 강사의 수동 협조가 있어야 지켜지는 약속(예: "24시간 우선 예약")은 화면에 쓰지 않는다. 어긋나면 그대로 CS가 되고, 강사 실수의 책임을 올빗이 지게 된다. 상태 문구도 실제로 일어난 일만 말한다 (예: "검토 중"은 강사가 누른 뒤에만).

### 1.3 사용자 역할

| 역할 | 설명 | 로그인 |
|---|---|---|
| 게스트 | 탐색만 하는 방문자 | 없음 |
| 수강생 | 카카오 로그인한 사용자. 추가요(요청) 가능 | 카카오 |
| 강사 | 강사 신청 후 운영자 승인을 받은 사용자. 클래스 등록 가능 | 카카오 |
| 운영자 | 우리 둘. 승인·곡 관리·대리 등록 | 별도 관리자 계정 |

한 사람이 수강생이자 강사일 수 있다 (같은 계정에 강사 프로필이 붙는 구조).

| 용어 | 정의 |

## 4. 기능 상세

### F-01. 홈
**목적**: 들어오자마자 "지금 뜨는 곡"과 "이번 주 클래스"가 보여야 한다.

**구성 (위에서 아래 순서)**
1. 검색창 (고정) — placeholder: "추고 싶은 곡이나 아티스트"
2. **이번 주 핫한 곡** — 이번 주(오늘~7일) 클래스가 있는 곡을 클래스 수 순으로 최대 10개. 곡 카드: **안무 영상 썸네일**(16:9, YouTube 출처 표시), 곡명, 아티스트, "클래스 N개". 영상이 없는 곡은 기본 그라데이션 이미지
3. **다가오는 클래스** — 오늘 이후 가장 가까운 클래스 10개 (클래스 카드)
4. **추가요 TOP 5** — 최근 30일 추가요가 많은 곡. "N명이 기다려요" + [나도 추가요!] 버튼 → F-08로 더보기

**규칙**
- 섹션에 보여줄 데이터가 0개면 섹션을 숨긴다 (빈 섹션 금지).
- 클래스 카드 공통 표시: 곡명 · 아티스트, 날짜(요일) 시간, 권역, 가격, 난이도, 상태 배지(마감 임박 / 마감)

**수용 기준**
- [ ] 비로그인 상태에서 홈이 3초 안에 보인다 (4G 기준)
- [ ] 클래스가 하나도 없을 때도 검색창과 추가요 섹션은 보인다

> 구현 메모 (2026-10-28, `specs/home`): 하단 탭바·섹션별 더보기는 갈 화면(U-03, F-08, U-09)이 생길 때 붙인다. 검색 입구는 F-02와 함께 붙였다 (MVP 원칙 6). 세 섹션이 모두 비면 "아직 열린 클래스도, 추가요도 없어요"만 보여준다. 다가오는 클래스 카드 제목은 클래스 이름 대신 "곡명 · 아티스트".

### F-02. 검색
**목적**: 곡명·아티스트·강사명 무엇을 쳐도 원하는 곡에 도달한다.

**동작**
- 입력 중 자동완성: 곡 (최대 5), 아티스트 (최대 3), 강사 (최대 3) 그룹으로 표시
- 자동완성에서 **곡 선택 → F-04 곡 상세**, 아티스트 선택 → 해당 아티스트 곡이 포함된 클래스 목록, 강사 선택 → 해당 강사 클래스 목록 (F-21 전까지는 목록으로)
- 엔터 → F-03 클래스 목록 (검색어 적용)

**검색 규칙**
- 곡명·아티스트명은 **별칭까지 검색** (예: "네온" → NEON, "에이투오" → A2O LITE)
- 대소문자·공백·특수문자 무시 ("a2o lite" = "A2O LITE" = "a2olite")
- 초성 검색은 MVP 제외

**결과 없음**
- "아직 'OO' 클래스가 없어요" + **[추가요! 이 곡 열어주세요]** 버튼 → F-07
- 검색어가 등록된 곡과 일치하지 않으면 F-13 신규 곡 등록 흐름으로 연결

**수용 기준**
- [ ] 곡 별칭으로 검색해도 같은 곡이 나온다
- [ ] 결과 없음 화면에서 두 번 이내 탭으로 추가요를 남길 수 있다

> 구현 메모 (2026-10-28, `specs/search`): 이번에는 곡·아티스트(별칭 포함) 검색만 하고 결과는 곡 상세로 간다. 강사 검색·클래스 목록(F-03)·엔터로 목록 열기는 화면이 생길 때. 결과 없음은 안내만 하고, 추가요로 잇는 것은 F-13과 함께. 운영자 클래스 등록의 곡 선택도 같은 검색을 쓴다(기본 한 곡, 최대 세 곡). 찾는 곡이 없으면 곡명·아티스트로 그 자리에서 만든다(F-13의 운영자 쪽, 같은 곡이면 기존 곡).

### F-03. 클래스 목록·필터
**필터**
| 필터 | 옵션 | 기본값 |
|---|---|---|
| 날짜 | 오늘 / 이번 주 / 이번 주말 / 날짜 직접 선택 | 오늘 이후 전체 |
| 권역 | 2.1 목록 다중 선택 | 전체 |
| 난이도 | 입문 / 초급 / 중급 이상 | 전체 |

**정렬**: 날짜 가까운 순 (MVP는 이것 하나)

**표시 규칙**
- 기본은 **모집중**·**마감 임박** 클래스만. "마감된 클래스도 보기" 토글
- 종료(일시가 지난)·취소된 클래스는 목록에 안 보인다
- 무한 스크롤, 한 번에 20개
- 필터 상태는 URL 쿼리에 남긴다 (공유 가능)

**수용 기준**
- [ ] 필터 조합 결과가 0개일 때 "조건을 줄여보세요" + 필터 초기화 버튼
- [ ] 목록 URL을 공유하면 같은 필터 결과가 열린다

### F-04. 곡 상세 페이지 ★ 서비스의 중심 화면
**목적**: 곡 하나에 대한 모든 것 — 열린 클래스, 기다리는 사람 수, 요청 버튼.

**구성**
1. 곡 헤더: **안무 영상** (YouTube 공식 임베드 플레이어, 16:9, 자동재생 끔, 탭하면 재생) + 영상 유형 표시(안무 연습 / 퍼포먼스 / MV) + [YouTube에서 보기]. 그 아래 곡명, 아티스트, 발매일(선택). 영상이 없으면 기본 그라데이션 이미지
2. **추가요 상태**: "N명이 이 곡 클래스를 기다려요" + 권역별 상위 3개 ("홍대권 12명")
3. **[추가요!]** 버튼 (이미 했으면 "추가요 완료 ✓ · 취소")
4. 이 곡의 다가오는 클래스 목록 (F-03 카드, 날짜순)
5. 클래스가 0개면: "아직 열린 클래스가 없어요. 추가요가 쌓이면 강사님들이 볼 수 있어요"
6. 강사에게만 보이는 영역: **[이 곡으로 클래스 열기]** → F-12 (곡 미리 선택됨)

**규칙**
- URL: `/song/{slug}` (예: `/song/a2o-lite-neon`). 인스타 공유 시 OG 이미지·제목이 곡 기준으로 보여야 한다
- OG 이미지는 YouTube 썸네일이 아니라 **올빗이 만든 이미지**(곡명·아티스트·올빗 로고)를 쓴다. YouTube 콘텐츠를 출처 표시 없이 외부 미리보기에 노출하지 않기 위해 [가정: 정책 해석, 출시 전 확인]
- 추가요 수는 전체 누적이 아니라 **최근 90일** 기준 [가정: 유행 주기 반영]

**수용 기준**
- [ ] 곡 URL을 카톡·인스타에 붙이면 곡명과 이미지가 미리보기로 뜬다
- [ ] 강사가 아닌 사용자에게 [클래스 열기] 버튼이 보이지 않는다

**안내 문구 (예약하기 버튼 위)**: "예약은 강사님의 OO(네이버 예약/오픈채팅 등)에서 진행돼요"

**상태별 버튼**
| 상태 | 버튼 |
|---|---|
| 모집중·마감 임박 | [예약하기] 활성 |

| 종료 | **[앵콜!]** (F-24, 종료 후 30일까지) + "같은 곡 다른 클래스 보기" |
| 취소 | 버튼 비활성, "같은 곡 다른 클래스 보기" + [이 곡 추가요!] (F-07) |

> 구현 메모 (2026-10-28, `specs/class-detail`): F-24 앵콜이 생기기 전까지 마감·종료 화면에는 [앵콜!]을 두지 않는다 (MVP 원칙 6). 종료는 자동 종료 배치가 생기기 전까지 종료 시각으로 판단한다. 정원은 숫자만 보여주고 남은 자리는 말하지 않는다.
>
> 구현 메모 (2026-11-03, `specs/encore`): 마감·종료(30일 이내) 화면의 하단 막대는 앵콜 패널이 대신한다.

### F-06. 예약 링크 이동 (클릭 기록)
- [예약하기]는 외부 URL로 바로 가지 않고 내부 경로 `/go/{classId}`를 거친다 → 클릭 1건 기록 후 외부로 리다이렉트
- 기록 항목: 클래스 ID, 시각, 로그인 사용자 ID(있으면), 유입 경로(referrer)
- 같은 사용자(또는 같은 브라우저)의 같은 클래스 클릭은 10분 안 중복 시 1회로 셈
- 외부 링크는 새 탭으로 연다
- 예약 링크 유형 표시: 네이버 예약 / 카카오 오픈채팅 / 인스타 DM / 구글폼 / 기타 (강사가 등록 시 선택, URL로 자동 추정 가능하면 자동 선택)

**수용 기준**
- [ ] 클릭 수가 운영자 지표(F-18)에 클래스별로 보인다
- [ ] 외부 링크가 깨졌을 때를 대비해 운영자가 링크를 수정할 수 있다

### F-07. 추가요 (요청하기) ★ 핵심 무기
**목적**: "이거 해주세요" 댓글을 모아 수요 데이터로 만든다.

**진입점**: 곡 상세(F-04), 검색 결과 없음(F-02), 마감된 클래스(F-05), 추가요 랭킹(F-08)

**입력**
| 항목 | 필수 | 메모 |
|---|---|---|
| 곡 | ✓ | 진입점에서 자동 선택. 없으면 F-13으로 선택/신규 등록 |
| 희망 권역 | ✓ | 1개 선택. "어디든 좋아요" 옵션 포함 |
| 희망 시간대 | | 평일 저녁 / 주말 낮 / 주말 저녁 / 상관없음 [가정: 강사에게 유용할 것] |
| 한마디 | | 최대 100자. "킬링파트만이라도!" 같은 것. 운영자·강사에게만 보임 |

**규칙**
- 로그인 필요. 비로그인 사용자가 누르면 카카오 로그인 → 완료 후 원래 화면으로 복귀하고 추가요 시트가 자동으로 열린다
- **사용자 1명 × 곡 1개 = 추가요 1건.** 이미 추가요한 곡에서 다시 누르면 수정(권역·시간대 변경) 또는 취소
- "나도 추가요"는 별도 기능이 아니라 같은 곡에 추가요를 남기는 것과 동일
- 추가요 후 확인 메시지: "추가요 완료! 강사님들이 볼 수 있게 모아둘게요". 알림(F-20, Should)을 만들면 "이 곡 클래스가 열리면 알려드릴게요"로 바꾼다 (MVP 원칙 6: 아직 없는 알림을 약속하지 않음, 2026-10-27 구현 시 변경)
- 취소 후 다시 추가요하면 같은 행을 `waiting`으로 되돌리고 생성 시각을 지금으로 바꾼다 → "최근 90일" 집계에 새 요청으로 잡힌다. "열렸어요" 상태는 수정해도 유지
- 추가요는 **집계로만 공개**한다. 누가 요청했는지는 다른 수강생에게 보이지 않는다

**상태**
| 상태 | 조건 |
|---|---|
| 대기중 | 기본 |
| 열렸어요 | 추가요 이후 같은 곡 클래스가 등록됨 (권역 무관). 해당 클래스로 링크 |
| 취소 | 사용자가 취소 |

**수용 기준**
- [ ] 같은 곡에 두 번 추가요해도 숫자가 1만 올라간다
- [ ] 비로그인 → 로그인 → 원래 곡 화면 복귀 → 추가요 완료까지 끊기지 않는다

### F-08. 추가요 랭킹
**목적**: 수강생에게는 "다른 사람도 원한다"는 재미, 강사에게는 **"이 곡 열면 사람 온다"는 수요 대시보드**.

**구성**
- 탭: 전체 / 권역별 (권역 선택)
- 기간: 최근 30일 (고정) [가정]
- 행: 순위, 곡 커버, 곡명·아티스트, 추가요 수, 이번 주 증가 수(▲N), 상태 ("클래스 N개 열림" 또는 "아직 없음")
- 각 행에 [나도 추가요!]
- **강사로 로그인 시** 각 행에 [이 곡으로 클래스 열기] + 펼치기 → 권역별 분포, 희망 시간대 분포, 한마디 최근 5개

**규칙**
- 추가요 수가 3 미만인 곡은 랭킹에 안 나온다 (노이즈 방지) [가정]
- 최대 50위까지

**입력 (한 화면)**

**상태 관리**

| 마감 임박 | 강사가 수동으로 표시 [가정: 외부 예약이라 잔여석을 모름] |

### F-13. 곡 선택·신규 곡 등록
**곡 선택**: 검색 자동완성 (F-02와 같은 규칙)에서 고른다.

**찾는 곡이 없을 때 → 신규 곡 등록**
| 항목 | 필수 |
|---|---|
| 곡명 | ✓ |
| 아티스트 | ✓ (기존 아티스트 자동완성, 없으면 새로 입력) |
| YouTube 영상 링크 | 선택 (아는 사람만. 안무 연습 영상 권장) |

**규칙**
- 신규 곡은 바로 쓸 수 있다 (등록을 막지 않는다)
- 대신 운영자 화면(F-16)에 "검수 대기 곡"으로 쌓이고, 운영자가 중복이면 **기존 곡으로 병합**한다. 병합 시 연결된 클래스·추가요가 모두 기존 곡으로 옮겨진다
- 곡의 대표 영상은 운영자가 검수 때 정한다 (F-16). 영상이 정해지기 전에는 기본 이미지 (아티스트 이니셜 + 그라데이션)
- 앨범 커버는 MVP에서 쓰지 않는다

**결정 (2026-10-26)**: 곡 정보는 외부 API로 자동 검색하지 않는다. 곡명·아티스트는 **우리 DB + 사람 입력**, 비주얼은 **YouTube 영상 ID만 저장**. YouTube API는 영상 정보만 주고 곡명·아티스트·발매일 같은 곡 정보는 정확히 주지 않으며, 공식 YouTube Music API는 없다. MVP는 곡이 수십 개라 수동 입력으로 충분하고, 곡이 수백 개로 늘면 자동화(Topic 채널 설명란, Deezer·Apple 텍스트 정보)를 재검토 (06 문서)

### F-15. 운영자: 대리 등록 (콘시어지) ★ 초기 공급의 핵심
**목적**: 인스타에 공지된 클래스를 운영자가 빠르게 옮겨 담는다.

**흐름**
1. **대리 강사 프로필 생성**: 활동명, 인스타 핸들, 권역. 이 프로필은 아직 카카오 계정과 연결되지 않은 "미연결" 상태
2. **동의 기록**: 강사에게 DM으로 게재 동의를 받은 날짜, 동의 방법(DM 캡처 등) 메모 **— 동의 기록 없이는 클래스 공개 불가**
3. 클래스 등록: F-12와 같은 폼을 운영자가 대신 입력. 썸네일은 강사가 보내준 이미지만
4. 공개된 클래스에는 "올빗이 대신 등록한 클래스예요" 표시를 하지 않는다 [가정: 신뢰 저하 우려] — 대신 강사 인스타 링크로 출처를 분명히 한다

**수용 기준**
- [ ] 운영자 1명이 클래스 1개를 2분 안에 대리 등록할 수 있다
- [ ] 동의 기록이 없는 대리 강사의 클래스는 공개 버튼이 비활성

### F-16. 운영자: 곡·아티스트 관리
- 곡 목록: 검색, 검수 대기 필터
- 곡 수정: 곡명, 아티스트, 별칭(여러 개), 발매일, slug, **대표 영상**
- **대표 영상 등록**: YouTube 링크를 붙여넣으면 영상 ID를 뽑고, YouTube API(`videos.list`)로 영상 제목·채널·썸네일·임베드 가능 여부를 자동으로 채운다. 운영자는 영상 유형만 고른다 (안무 연습 / 퍼포먼스 / MV)
  - 우선순위: 공식 채널의 안무 연습 영상 > 퍼포먼스 영상 > MV
  - 임베드가 막힌 영상은 등록 불가 (안내 메시지)
- **영상 정보 갱신**: 저장한 영상 정보는 30일마다 자동 갱신 (YouTube 정책). 영상이 삭제·비공개·임베드 차단으로 바뀌면 곡 상세에서 영상 영역을 숨기고 운영자 화면에 "영상 교체 필요" 표시
- YouTube 영상 **검색**은 API로 하지 않는다 (하루 100회 제한). 운영자가 YouTube에서 직접 찾아 링크를 붙여넣는다
- **곡 병합**: A를 B로 병합 → A의 클래스·추가요·별칭이 B로 이동, A의 URL은 B로 리다이렉트
- 아티스트 수정·병합 (같은 방식)

### F-17. 운영자: 클래스 관리
- 전체 클래스 목록: 상태·강사·곡·권역 필터
- 숨김 (신고·오류 시), 예약 링크 수정, 강제 마감/종료

### F-18. 운영자: 지표
기획서 6절 성공 지표를 한 화면에서 본다.
| 지표 | 정의 |
|---|---|
| 등록된 클래스 수 | 누적 / 이번 주, 대리 등록 vs 강사 직접 등록 구분 |
| 자발적 등록 강사 수 | 클래스를 직접 등록한 적 있는 강사 수 |
| 예약 링크 클릭 | 누적 / 클래스별 |
| 요청 → 개설 전환 | 추가요가 있던 곡 중 이후 클래스가 열린 곡 수 |
| 재방문 | 가입 후 2주 안에 다른 날 다시 접속한 사용자 수 |
| 추가요 수 | 누적 / 곡별 |
| 앵콜 → 개설 전환 | 앵콜 기준을 넘은 클래스 중 앵콜 클래스가 실제로 열린 비율 |

MVP는 표 형태로 충분. 차트는 나중에.

### F-24. 앵콜 (마감·종료 클래스 재오픈 요청) ★ 2026-10-26 추가
**목적**: 마감되거나 끝난 클래스에 "한 번 더 열어주세요"를 모아서, 일정 수가 넘으면 강사에게 전달하고 **앵콜 클래스(새 회차)** 개설로 연결한다. 돈을 받지 않는 펀딩 같은 구조.

**추가요(F-07)와의 차이**
| | 추가요 | 앵콜 |
|---|---|---|
| 대상 | **곡** (어떤 강사든) | **특정 강사의 특정 클래스** |
| 받는 사람 | 그 곡에 관심 있는 모든 강사 | 그 클래스의 강사 1명 |
| 결과물 | 누군가 그 곡 클래스를 연다 | 같은 강사가 같은 클래스를 **새 날짜로** 다시 연다 |

**진입점**: 클래스 상세(F-05)에서 상태가 **마감** 또는 **종료(종료 후 30일 이내)** 일 때 [앵콜!] 버튼

**입력 (바텀시트, 최소)**
| 항목 | 필수 | 메모 |
|---|---|---|
| 희망 시간대 | | 평일 저녁 / 주말 낮 / 주말 저녁 / 상관없음 |
| 한마디 | | 최대 100자. 강사에게만 보임 |

**규칙**
- 로그인 필요 (추가요와 같은 로그인 복귀 흐름)
- 사용자 1명 × 클래스 1개 = 앵콜 1건. 다시 누르면 취소
- **앵콜은 예약이 아니라 관심 표시다.** 인원을 "확정"하지 않으며, 취소는 어느 상태에서든 막지 않는다 (막아도 실제 예약은 보장되지 않고 사용자 반감만 생김)
- **상태는 뒤로 가지 않는다.** "전달됨"·"검토 중"이 된 뒤 취소로 인원이 기준 아래로 내려가도 상태를 유지한다
- **취소 확인 창** (전달됨·검토 중 상태에서 취소할 때): "취소하면 강사님이 보는 앵콜 인원에서 빠져요." — 사실만 말하고, 혜택 상실 같은 위협 문구는 쓰지 않는다
- 수강생 화면의 인원은 항상 **실제 현재 인원**을 보여준다
- **앵콜 기준 인원**: 정원이 있으면 정원의 30% (최소 3명), 정원이 없으면 5명 [가정]
- 앵콜 요청은 원 클래스 종료 후 **30일**이 지나면 만료 [가정]

**수강생에게 보이는 상태 문구** — 실제로 일어난 일만 말한다
| 상태 | 조건 | 문구 |
|---|---|---|
| 모으는 중 | 기준 미달 | "N명이 앵콜을 기다려요 · M명 더 모이면 강사님께 전달돼요" (진행 바) |
| 전달됨 | 기준 도달, 강사 미응답 | "앵콜 요청이 강사님께 전달됐어요!" |
| **검토 중** | 강사가 [검토할게요] 누름 | **"많은 요청으로 강사님이 앵콜을 검토 중이에요!"** |
| 앵콜 오픈 | 강사가 앵콜 클래스 등록 | "앵콜 클래스가 열렸어요!" → 새 클래스로 이동 |
| 이번엔 어려워요 | 강사가 [어려워요] 누름 | "이번엔 앵콜이 어렵대요" + 같은 곡 다른 클래스 / [이 곡 추가요!] |
| 만료 | 30일 경과 | 버튼 숨김. 같은 곡 다른 클래스 / 추가요 안내 |

> "검토 중" 문구는 강사가 실제로 응답했을 때만 보여준다. 기준만 넘었는데 "검토 중"이라고 쓰면 사실이 아니고, 강사가 응답하지 않으면 신뢰가 깨진다.

**강사 쪽**
- 기준 도달 시 내 클래스(T-03)에 "앵콜 N명 · 응답 필요" 배지
- 클래스별 앵콜 상세: 인원, 희망 시간대 분포, 한마디 최근 5개
- **인원은 두 숫자로 보여준다**: "검토 시작 시점 14명 · 지금 12명 (취소 2)". [검토할게요]를 누른 순간의 인원을 기준점으로 저장
- **기대치 안내 (고정 문구)**: "앵콜은 예약이 아니라 관심 표시예요. 앵콜한 분 전원이 예약하지는 않을 수 있어요." — "14명이라더니 6명 왔다"는 강사 CS를 미리 막는 장치
- 나중에 데이터가 쌓이면 "앵콜 인원 대비 실제 예약 클릭 비율"(앵콜한 사용자의 앵콜 클래스 `/go` 클릭)을 근거로 보여준다. 약속이 아니라 통계로
- 응답 버튼 3개:
  - **[검토할게요]** → 상태 "검토 중"
  - **[앵콜 클래스 열기]** → F-12 "복사해서 만들기"로 이동 (곡·장소·가격·링크 복사, 날짜만 입력). 저장 시 원 클래스와 연결
  - **[이번엔 어려워요]** → 상태 종료, 요청자들에게 대체 안내
- "검토 중"에서 14일 동안 다음 응답이 없으면 운영자에게 알림 (운영자가 강사에게 확인) [가정]

**강사에게 전달하는 방법 (MVP)**
- 강사 알림 기능이 아직 없으므로 **운영자가 수동으로 DM** — 운영자 지표 화면(F-18)에 "앵콜 기준 도달, 강사 미응답" 목록을 띄운다
- 대리 등록 강사(미연결)의 클래스도 똑같이 운영자가 DM으로 전달 → 강사 유입의 좋은 계기 ("선생님 클래스 앵콜 요청이 12명이에요")
- 자동 알림(카카오 알림톡 등)은 F-20과 함께 Should

**앵콜 클래스가 열리면**
- 새 클래스에 "앵콜 클래스" 배지 + 원 클래스 링크
- 앵콜 요청자들의 상태 → 앵콜 오픈. 알림은 F-20 (Should), 그 전까지는 마이페이지 "내 앵콜"에서 확인
- 원 클래스 상세에 "앵콜 클래스가 열렸어요 →" 배너

**수용 기준**
- [ ] 기준 인원에 도달하는 순간 운영자 지표에 해당 클래스가 나타난다
- [ ] 강사가 응답하기 전에는 수강생 화면에 "검토 중" 문구가 나오지 않는다
- [ ] 앵콜 클래스를 열면 원 클래스의 앵콜 요청자 전원의 상태가 바뀐다
- [ ] 같은 사용자가 같은 클래스에 두 번 앵콜하면 숫자가 1만 오른다
- [ ] 검토 중에 취소가 생겨 기준 아래로 내려가도 상태가 "검토 중"으로 유지되고, 강사 화면에 검토 시작 시점 인원과 현재 인원이 함께 보인다
- [ ] 화면 어디에도 "우선 예약"처럼 시스템이 보장하지 못하는 혜택 문구가 없다

**하지 않는 것 (MVP)**
- 앵콜 참여자 **우선 예약**: 외부 예약 채널을 우리가 통제하지 못해 강사 협조가 필요하고, 어긋나면 CS가 된다. 결제·예약 내재화(기획서 C1) 이후 시스템으로 보장할 수 있을 때 도입
- 앵콜 인원 확정·예약금: 결제 내재화 이후

> 구현 메모 (2026-11-03, `specs/encore`): 강사 화면(T-03)과 알림이 없어 운영자가 운영 앵콜 화면에서 강사에게 DM으로 전하고 강사의 답(검토할게요·이번엔 어려워요·앵콜 클래스 등록)을 대신 남긴다. 앵콜 클래스는 운영자 클래스 등록에서 원 클래스 값을 미리 채우고 강사를 고정한다. 마감은 운영자가 다가오는 클래스 목록에서 바꾸고(F-17 일부), 앵콜이 한 번도 없던 클래스만 마감을 풀 수 있다. 만료는 저장하지 않고 읽을 때 계산한다. 마이 "내 앵콜"(F-10), 검토 중 14일 무응답 알림은 아직 없다.

### Should 기능 (출시 후 2~4주)

#### F-19. 대리 등록 강사의 계정 연결 (클레임)
- 강사가 강사 신청(F-11) 시 입력한 인스타 핸들이 미연결 대리 프로필과 같으면 "이미 올빗에 등록된 클래스가 있어요. 내 계정으로 가져올까요?" 안내
- 인증 코드 확인 후 대리 프로필과 클래스가 강사 계정으로 이전

#### F-20. 추가요한 곡 클래스 열림 알림
- 추가요(대기중)한 곡에 새 클래스가 등록되면 알림
- 채널: 카카오 알림톡 (비즈 채널 필요) 또는 웹 푸시 — 기술 설계에서 결정
- 같은 사용자에게 하루 최대 3건

#### F-21. 강사 프로필 페이지
- `/teacher/{handle}`: 활동명, 소개, 인스타 링크, 다가오는 클래스, 지난 클래스 (곡 목록)

#### F-22. 찜
- 클래스 찜. 마이페이지에서 목록. 찜한 클래스가 마감·취소되면 표시

#### F-23. 인스타 스토리 공유 이미지
- 클래스 상세에서 [스토리용 이미지 만들기] → 9:16 이미지 (곡명, 일시, 권역, 올빗 로고, 링크 스티커용 URL 안내)
- 목적: 강사가 인스타 스토리에 올빗 링크를 걸게 하는 장치

#### F-25. 강사 티저 영상
- 클래스 등록(F-12)에 선택 입력 "티저 영상 링크" (YouTube 일반 영상·쇼츠)
- 있으면 클래스 상세 상단에 임베드 → "이 강사는 이렇게 가르쳐요"
- 등록 규칙은 F-16 대표 영상과 같음 (임베드 가능 여부 확인, 30일 갱신)
- 인스타 릴스는 임베드 정책이 달라 MVP 이후 검토
