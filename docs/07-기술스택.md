## 2. 후보 비교

| | **A. Next.js 풀스택 + Supabase** | B. Next.js + Spring Boot(Kotlin) | C. Next.js on Cloudflare + Supabase |
|---|---|---|---|
| 코드베이스 | **1개** | 2개 (프론트·백엔드) | 1개 |
| 배포 | Vercel 1곳 | Vercel + JVM 서버 | Cloudflare Workers |
| 무료 운영 | ✅ Vercel Hobby + Supabase Free | ⚠️ JVM 상시 서버를 무료로 돌릴 곳이 거의 없음 (잠들거나 유료) | ✅ 상업적 이용 제약이 적음 |
| 개발 속도 (1인) | **가장 빠름**. 화면·서버 로직·DB를 한 언어로 | 느림. API 계약·인증 연동·배포를 두 번 | 빠르지만 Next.js 어댑터(OpenNext) 설정·제약을 익혀야 함 |
| 익숙함 | ✅ | ✅ | ⚠️ 새로 배울 것 있음 |
| 나중에 커지면 | 무거운 로직만 별도 서비스로 분리 가능 | 처음부터 확장 구조 | A와 같음 |

**결정: A. Next.js 풀스택 + Supabase**

- MVP의 서버 로직은 대부분 "폼 저장, 목록 조회, 집계"라 별도 백엔드가 필요한 무게가 아니다
- Spring은 익숙하지만, 1인 MVP에서 백엔드를 분리하면 **일이 두 배**가 되고 **무료로 띄울 곳도 마땅치 않다**
- 결제·정산(기획서 C1)처럼 무거운 기능이 생기면 그때 그 부분만 Spring 서비스로 떼어낼 수 있다

### 2.1 별도 Node 백엔드(NestJS)는? — 지금은 쓰지 않는다

MVP 서버 작업은 전부 **짧은 요청-응답**이다 (폼 저장, 목록·랭킹 조회, `/go` 리다이렉트, 하루 1회 배치). 실시간 연결·오래 걸리는 작업·작업 큐가 없다.

| Nest를 추가하면 | |
|---|---|
| 일 | API 엔드포인트 + 프론트 호출 코드 + 두 서버 간 인증 공유 → 두 배 |
| 비용·속도 | 항상 켜진 Node 서버 필요. 무료 호스팅은 유휴 시 잠들어 첫 요청에 수십 초 → 인스타 유입 사용자 이탈 |
| 운영 | 배포·환경변수·장애 지점 두 곳 |

**Nest(또는 별도 백엔드)가 필요해지는 시점**
| 상황 | 기획서 |
|---|---|
| 네이티브 앱이 웹과 같은 API를 써야 할 때 | C5 |
| 결제·정산 (웹훅, 정산 배치, 재시도 큐) | C1 |
| 대량 알림 발송 작업 큐 | F-20 이후 |
| 개발자가 늘어 프론트·백엔드를 나눠 맡을 때 | - |

**그래서 처음부터 떼기 쉽게 짓는다** (6절 구조)
- 비즈니스 로직은 `src/server/`에 **순수 TypeScript**로만 둔다 (Next.js import 금지)
- 서버 액션·Route Handler는 `server/` 함수를 부르기만 하는 **얇은 층**
- 네이티브 앱이 먼저 오면 Next.js에 `/api/v1/...`를 열어 같은 `server/` 함수 재사용
- 백엔드 분리가 필요해지면 `server/`를 Nest 서비스로 거의 그대로 이전

## 3. 확정 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | **TypeScript** | 프론트·서버 한 언어 |
| 프레임워크 | **Next.js (App Router)** | 서버 렌더링 + OG 태그(곡·클래스 공유), 서버 액션으로 폼 처리, Route Handler로 `/go/{id}` 리다이렉트 |
| UI | **Tailwind CSS + shadcn/ui** | 와이어프레임의 칩·시트·탭을 빠르게. 컴포넌트 코드를 직접 소유 |
| 폼·검증 | **react-hook-form + zod** | 클래스 등록 폼 검증 (필수 7개, URL 형식, 과거 날짜 금지). zod 스키마를 서버에서도 재사용 |
| DB | **Supabase Postgres** | 관계형 데이터(곡·클래스·추가요·앵콜), 무료 500MB로 MVP 충분 |
| ORM | **Drizzle ORM** | ERD가 쓰는 Postgres 기능(부분 인덱스 4개, CHECK 제약, RLS 정책, `pg_trgm` GIN, `FILTER` 집계)을 **TypeScript 스키마 한 곳에** 담을 수 있음. Prisma는 CHECK·RLS를 마이그레이션 SQL에 손으로 넣어야 해서 두 군데로 갈라짐. (Prisma 7은 엔진을 없애 "서버리스에서 무겁다"는 차이는 거의 사라짐) |
| 인증 | **Supabase Auth — Kakao 제공자** | 카카오 공식 지원, "이메일 없는 사용자 허용" 옵션으로 **닉네임·ID만** 받기 가능 (F-09). 운영자는 같은 Auth에 이메일 로그인 + DB 역할(role) |
| 권한 | Postgres **RLS** + 서버 코드 검사 | 강사는 자기 클래스만 수정, 운영자만 /admin |
| 파일 저장 | **Supabase Storage** | 클래스 썸네일 업로드. 업로드 시 리사이즈 |
| 배치(크론) | **Vercel Cron** (하루 1회) | 클래스 종료 자동 처리, 앵콜 30일 만료, 검토 중 14일 무응답 알림, YouTube 영상 정보 30일 갱신. Hobby는 하루 1회·시간 오차 ±59분 → 우리 배치에는 충분 |
| 주소 검색 | **다음(카카오) 우편번호 서비스** | 무료, 키 불필요. 결과의 시군구·동으로 **권역 자동 매핑** (우리 매핑표) |
| 지도 | 지도 앱 **링크로 열기** (네이버·카카오맵) | 지도를 화면에 그리지 않음 (MVP 범위 밖) |
| 영상 | **YouTube Data API v3** (`videos.list`만) + 공식 임베드 | 06 문서. API 키는 서버 환경변수에만 |
| 에러 모니터링 | **Sentry** 무료 플랜 | 1인 운영에서 장애를 먼저 알아야 함 |
| 지표 | **자체 이벤트 테이블** (조회·예약 클릭·추가요·앵콜) + 필요하면 GA4 | 성공 지표(기획서 6절)는 우리 DB에서 바로 집계 |
| 호스팅 | **Vercel** | Next.js 기본 배포처, 미리보기 배포, 크론 내장 |
| 코드 관리 | GitHub `wecaners/All-The-Beat`, `main` + 기능 브랜치 | |

## 4. 무료 티어로 버티기 — 알아야 할 제약

| 서비스 | 무료 한도 (2026년 기준, 출시 전 재확인) | 우리에게 주는 영향 |
|---|---|---|
| **Vercel Hobby** | **개인·비상업 용도만**. 광고·결제·제휴 수익이 생기면 Pro($20/월) 필요. 크론 하루 1회 | ⚠️ **수익이 생기기 전까지만** Hobby. 광고·수수료·제휴(예: 나중의 Apple 제휴)를 붙이는 순간 Pro로 전환 |
| **Supabase Free** | DB 500MB, 인증 월 5만 명, 프로젝트 2개. **7일 동안 활동이 없으면 일시 정지** | 개발 기간에 며칠 손 놓으면 멈출 수 있음 (대시보드에서 다시 켜면 됨). 출시 후 실사용자가 있으면 정지되지 않음. 안정성이 필요해지면 Pro($25/월) |
| **YouTube Data API** | 하루 10,000 units, 검색은 하루 100회 | 곡마다 영상 ID 저장 방식이라 충분 (06 문서) |
| **Sentry** | 무료 플랜 이벤트 한도 | MVP 규모엔 충분 |

**예상 비용**
| 단계 | 월 비용 |
|---|---|
| 개발 ~ 베타 (수익 없음) | **0원** (+ 도메인 연 몇만 원) |
| 수익 모델 도입 후 | Vercel Pro $20 (+ 필요 시 Supabase Pro $25) |

> Cloudflare(후보 C)는 상업적 이용 제약이 적어서, 나중에 Vercel Pro 비용이 부담되면 옮겨갈 수 있는 **탈출구**로 남겨둔다.

## 6. 프로젝트 구조 (초안)

```
All-The-Beat/
├── docs/                 # 기획·설계 문서 (지금까지 작업)
├── wireframes/           # HTML 와이어프레임
├── scripts/
└── app/                  # Next.js 앱 (개발 시작 시 생성)
    ├── src/app/          # 라우트·화면·서버 액션 (얇게): (user) / me / admin / go/[id] / api/cron
    ├── src/server/       # ★ 비즈니스 로직 (순수 TS, Next.js 의존 없음)
    │   ├── songs/        #   곡·별칭·병합·대표 영상
    │   ├── classes/      #   등록·상태 변경·복사
    │   ├── requests/     #   추가요·랭킹 집계
    │   ├── encores/      #   앵콜·라운드 상태 전이
    │   └── jobs/         #   하루 1회 배치 로직
    ├── src/components/   # shadcn/ui 기반 컴포넌트
    ├── src/db/           # Drizzle 스키마·마이그레이션
    └── src/lib/          # 인증, YouTube 클라이언트, 권역 매핑, 검색 정규화
```

**규칙**: `src/app/` → `src/server/` → `src/db/` 한 방향으로만 의존한다. `src/server/`는 `next/*`를 import하지 않는다.
