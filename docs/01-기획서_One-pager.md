---

## 1. 한 문장 정의

**지금 유행하는 K-pop 곡의 오프라인 원데이 댄스 클래스를 곡·아티스트로 찾고, 없으면 열어달라고 요청하는 서비스.**

## 2. 문제

개인 댄스 강사의 원데이 클래스는 인스타 스토리에 공지되고 DM·네이버 예약 링크·계좌 입금으로 접수된다.

- **수강생**: 어떤 곡의 클래스가 이번 주에 어디서 열리는지 한눈에 볼 곳이 없다. 스토리는 24시간 뒤 사라지고, 팔로우한 강사의 수업만 알게 된다. 원하는 곡은 댓글로 "이거 해주세요"라고 적는 것 말고는 방법이 없다.
- **강사**: DM으로 선착순·정원·입금 확인을 수작업으로 한다. 어떤 곡을 열어야 사람이 올지는 감으로 정한다.
- **기존 플랫폼(탈잉·숨고·솜씨당)**: 댄스는 수백 카테고리 중 하나. 곡 단위 검색이 없고 1:1 레슨·정규반 위주라 "이번 주 원데이" 탐색에 맞지 않는다.

## 3. 타깃 사용자

| 구분 | 1차 타깃 | 메모 |
|---|---|---|
| 수강생 (주 사용자) | 20대, 서울 거주, 취미로 K-pop 커버댄스를 추는 사람. 신곡이 나오면 그 안무를 배우고 싶어 한다. 특정 강사보다 **곡**을 보고 움직인다 | 정규반 수강생·전공생은 1차 제외 |
| 강사 (공급자) | 인스타 팔로워 1천~3만 규모의 **개인 강사**. 스튜디오를 대관해 원데이 클래스를 연다 | 학원·대형 스튜디오는 1차 제외 (자체 시스템 있음) |

페르소나는 인터뷰 후 작성.

## 4. 해결책 (핵심 가치)

1. **곡으로 찾는다** — "NEON", "A2O LITE"로 검색하면 이번 주 서울의 해당 곡 클래스가 날짜·지역순으로 나온다.
2. **요청하면 열린다** — 원하는 곡·지역을 요청하고 다른 사람이 "나도"를 누른다. 강사는 "이 곡 요청 37명, 홍대권 20명"을 보고 클래스를 연다.
3. **강사는 하던 대로** — 강사는 1분 안에 클래스를 등록하고, 예약은 기존 링크(네이버 예약·오픈채팅·DM)로 받는다. 우리는 노출 채널을 하나 더 주는 것이지 인스타를 대체하지 않는다.

## 5. 왜 우리가, 왜 지금

- 곡 중심 탐색 + 요청 집계 조합은 국내외에 없다 (00-리서치 참고).
- K-pop 안무 수요는 STEPIN·SPARKY 같은 연습 앱이 글로벌로 크고 있을 만큼 검증돼 있다. 오프라인 탐색만 비어 있다.
- 댄스 버티컬은 혼자서도 범위를 잡을 수 있을 만큼 좁고, 커버댄스 문화가 가장 두터운 서울에서 시작할 수 있다.

## 6. 성공 기준 (MVP 출시 후 8주)

1차 목표는 **출시 자체**다. 아래 지표는 "다음 단계로 갈지 판단할 최소 신호"이며, 보수적으로 잡는다.

| 지표 | 목표 | 왜 이 지표인가 |
|---|---|---|
| 공개 출시 | 8주차에 누구나 접속 가능한 URL | 이게 1순위 |
| 등록된 클래스 수 | 누적 30개 (콘시어지 포함) | 빈 화면이 아닌 상태로 출시했는가 |
| 자발적 등록 강사 수 | 3명 | 콘시어지가 아닌, 강사가 스스로 올린 사례가 **존재**하는가 |
| 예약 링크 클릭 | 누적 50회 | 탐색이 수강 의도로 이어진 사례가 존재하는가 |
| 요청 → 개설 전환 | 요청된 곡 중 1곡이라도 실제 클래스 개설 | 요청 기능이 한 번이라도 작동했는가 (핵심 가설) |
| 재방문 | 가입자 중 2주 안에 다시 온 사람 10명 | 신곡 주기로 돌아오는 사람이 존재하는가 |

## 7. 검증해야 할 가설 (인터뷰 전까지 "믿음"일 뿐)

| # | 가설 | 틀리면 어떻게 되나 |
|---|---|---|
| H1 | 수강생은 강사보다 **곡**을 보고 클래스를 고른다 — **대전제로 채택** (2026-10-26). 인터뷰에서는 반증만 확인 | 초기엔 네임밸류 높은 강사가 들어오지 않으므로 곡 중심이 맞다. 유명 강사 인입 시 "OO의 수업" 강사 필터를 추가 (Could C6) |
| H2 | 수강생은 팔로우하지 않은 강사의 클래스도 **발견만 되면** 간다 | 발견 자체의 가치가 낮음 → 서비스 전제 흔들림 |
| H3 | 강사는 DM 접수 관리를 **실제로 불편해한다** | 강사 유입 동기를 "노출·수요 데이터"로만 설계해야 함 |
| H4 | 강사는 요청 수요가 보이면 그 곡으로 클래스를 **연다** | 요청 기능이 게시판에 그침 → 2차로 미룸 |
| H5 | 강사는 외부 링크로 예약을 받는 구조를 **거부하지 않는다** | 결제 내재화를 1차에 넣어야 함 (범위 커짐) |

인터뷰 대상: 수강생 5명, 개인 강사 3명. 질문지는 02 문서로 분리.

## 8. MVP 범위

### 원칙
- **수강생 쪽 가치(탐색·요청)에 집중**하고, 강사 쪽은 등록 최소 폼만.
- **결제·예약은 내재화하지 않는다.** 외부 링크 연결로 끝.
- **초기 공급은 우리가 직접 채운다.** 인스타 공개 클래스를 강사 동의 받아 등록 (콘시어지).
- 웹(모바일 우선) 한 개로 시작. 네이티브 앱은 2차.

### Must (이게 없으면 출시 안 함)
| ID | 기능 | 설명 |
|---|---|---|
| M1 | 클래스 목록·검색 | 곡명·아티스트·강사명 검색. 날짜·지역 필터. 기본 정렬은 가까운 날짜순 |
| M2 | 클래스 상세 | 곡, 아티스트, 강사, 일시, 장소, 가격, 난이도, 정원, 설명, 강사 인스타 링크, **예약하기 버튼(외부 링크)** |
| M3 | 곡 요청 | 곡·아티스트·희망 지역 입력. 같은 곡 요청은 자동 합산. "나도 원해요" 버튼 |
| M4 | 요청 랭킹 | 요청 많은 곡 순위 (전체 / 지역별). 강사가 보는 수요 대시보드 역할 |
| M5 | 강사 클래스 등록 | 로그인 후 폼 1개. 필수 입력 7개 이하. 요청 랭킹에서 "이 곡으로 클래스 열기" 진입 가능 |
| M6 | 로그인 | 카카오 로그인 1개. 수강생은 요청·"나도"에만 필요, 탐색은 비로그인 |
| M7 | 운영자 등록 도구 | 우리가 콘시어지로 클래스를 빠르게 올리는 관리 화면 (강사 계정 대리 생성 포함) |

### Should (출시 후 2~4주 안에)
| ID | 기능 |
|---|---|
| S1 | 곡 알림 — 요청한 곡의 클래스가 열리면 알림 (카카오 알림톡 or 이메일) |
| S2 | 강사 프로필 페이지 — 과거 클래스, 인스타 임베드 |
| S3 | 찜 / 최근 본 클래스 |
| S4 | 클래스 공유 — 인스타 스토리용 이미지 자동 생성 (강사가 우리 링크를 스토리에 올리게 하는 장치) |

### Could (수요 확인 후)
| ID | 기능 |
|---|---|
| C1 | 예약·결제 내재화 (PG, 정산, 환불) |
| C2 | 리뷰·평점 |
| C3 | 강사 수요 대시보드 고도화 (지역·시간대·연령) |
| C4 | 외국인 관광객 대상 영어 버전 |
| C5 | 네이티브 앱 |
| C6 | 강사별 필터 / "OO의 수업" 큐레이션 — 네임밸류 높은 강사 인입 시 |

### 1차에서 명시적으로 안 하는 것
- 결제, 정산, 환불 — 네이버 예약이 이미 한다
- 채팅 — DM과 오픈채팅이 이미 한다
- 학원·스튜디오 입점
- 정규반·1:1 레슨
- 영상 콘텐츠·안무 튜토리얼

## 9. 수익 모델 (지금은 안 받음, 방향만)

- 1차: 무료. 공급·수요 양쪽을 모으는 게 우선.
- 후보: (a) 강사 상단 노출 광고, (b) 결제 내재화 후 수수료 5~10%, (c) 강사용 수요 데이터 구독.
- 결정은 H3·H4 검증 후.

## 10. 리스크

| 리스크 | 대응 |
|---|---|
| 강사가 안 올린다 (닭과 달걀) | 콘시어지 등록으로 첫 8주 공급 보장. 아는 강사 1~2명 확보가 선결 과제 |
| 강사 인스타 사진·정보 사용 동의 | 등록 전 DM으로 동의 받고, 동의 이력 남김. 사진은 강사 제공분만 |
| "요청"이 그냥 게시판이 됨 | 강사에게 요청 수를 직접 보내주는 수동 운영 병행 (주 1회 "이번 주 요청 TOP 5" DM) |
| 네이버 예약이 곡 검색을 추가함 | 가능성 낮지만 있음. 요청·커뮤니티 데이터가 해자 |
| 두 사람 다 수강생이 아님 | 인터뷰 8명 전에 UI 확정 안 함. 출시 후 현장 방문 2회 |
