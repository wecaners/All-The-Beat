# 제품 원칙

기능을 기획하거나, 화면 문구를 쓰거나, 범위를 판단할 때 읽는다.
원문은 `docs/01-기획서_One-pager.md`와 `docs/03-기능명세서.md`다. 이 파일은 판단에 필요한 요점만 모은다. 원문과 다르면 원문이 맞고, 이 파일을 고친다.

## 한 문장

지금 유행하는 K-pop 곡의 오프라인 원데이 댄스 클래스를 **곡으로 찾고**, 없으면 **"추가요!"**, 마감됐으면 **"앵콜!"**로 요청하는 모바일 웹 서비스.

## MVP 원칙 (`docs/03` 1.2절)

1. **곡이 주인공이다.** 모든 탐색의 출발점은 곡(과 아티스트)이다. 강사로 고르는 기능은 나중이다.
2. **예약·결제는 하지 않는다.** "예약하기"는 강사의 기존 링크로 보낸다.
3. **강사는 하던 대로.** 등록은 1분, 입력 필드는 최소.
4. **초기 공급은 운영자가 채운다.** 운영자 대리 등록(콘시어지)이 1급 기능이다.
5. **비로그인으로 다 본다.** 로그인은 "추가요"와 강사 등록에만 필요하다. (앵콜도 추가요와 같은 로그인 흐름을 쓴다, F-24)
6. **시스템이 보장할 수 있는 것만 약속한다.** 강사의 수동 협조나 아직 없는 기능이 있어야 지켜지는 약속은 화면에 쓰지 않는다. 상태 문구는 실제로 일어난 일만 말한다.

원칙 6의 실제 적용 예:

- 알림(F-20)이 없으므로 추가요 완료 문구에서 "알려드릴게요"를 뺐다.
- "24시간 우선 예약"은 강사 협조가 필요해 MVP에서 뺐다.
- 앵콜 "검토 중"은 강사가 누른 뒤에만 보인다. 앵콜 취소는 막지 않고, 상태는 뒤로 가지 않는다.

## 핵심 개념

| 용어 | 뜻 |
| --- | --- |
| 곡 | 클래스·요청의 기준 단위. 곡명 + 아티스트. 표기가 달라도 별칭(alias)으로 하나로 묶는다 |
| 클래스 | 특정 일시·장소의 1회성 원데이 수업. 곡 1~3개와 연결 |
| 권역 | 사람들이 실제로 말하는 동네 묶음 8개 (서울 한정) |
| 추가요 | "이 곡 클래스 열어주세요" 요청. 사용자 1명 × 곡 1개 = 1건. 집계로만 공개 |
| 앵콜 | 마감·종료된 클래스를 다시 열어 달라는 요청. 기준 인원이 모이면 강사에게 전달 |
| 예약 링크 | 강사가 실제로 예약받는 외부 URL. `/go/{id}`를 거쳐 클릭을 센다 |

## 화면 문구

- 대화체·짧은 문장. 타깃은 10~30대다.
- 영상은 YouTube 공식 임베드만 쓰고 출처를 표시한다. 앨범 커버는 MVP에서 쓰지 않는다.
- 누가 요청했는지는 다른 수강생에게 보이지 않는다. 숫자로만 보여준다.

## 하지 않는 것 (MVP)

`docs/03` 8절을 기준으로 한다. 범위가 애매하면 그 절을 다시 읽고, 없으면 묻는다.
