## 사용자 지시 없이 커밋 금지

이 스킬이 불렸다는 사실은 커밋 승인이 아니다.
커밋 직전에 묻는다: **"사용자가 이번 세션에서 커밋을 지시했는가?"** 아니면 커밋하지 않는다.

"작업이 끝났으니", "다음 단계가 커밋이니", "지난번에도 커밋했으니"는 지시가 아니다.

## 절차

1. 이 파일을 Read로 연다.
2. `_agent/skills/verify`를 마지막 편집 뒤에 돌렸는지 확인한다. 아니면 먼저 돌린다.
3. `git status --short`로 무엇이 들어가는지 본다.
   - `.env*`(예시 파일 제외), 비밀값, `node_modules`, 임시 파일이 없는지 확인한다.
   - 관련 없는 변경이 섞여 있으면 묻는다. 하나의 의도는 하나의 커밋이다. 의도가 여럿이면 나눈다.
4. `git diff --cached`로 내용을 파악하고 메시지를 쓴다.
5. 아래 체크리스트를 통과하면 커밋한다.
6. `git log -1 --format=%B`로 실제 들어간 메시지와 트레일러를 확인한다.
7. 작성자가 `wade <wecaners1@gmail.com>`인지 `git log -1 --format='%an <%ae>'`로 확인한다.

## 메시지 형식

```text
<제목: 명사구, prefix 없음>

<본문: 왜 필요했는가 → 무엇을 이루려 하는가 → 무엇이 달라지는가.
현재형 존댓말(합니다체). 문단·불릿으로 자연스럽게.>

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

예:

```text
곡 상세 페이지와 추가요 저장·수정·취소

곡 상세는 서비스의 중심 화면이지만 지금까지는 가짜 데이터로 된 검증
페이지뿐이었습니다. 실제 곡 데이터를 읽고 추가요를 DB에 남기게 해서
수요가 쌓이기 시작하도록 합니다.

추가요는 사용자와 곡마다 한 건만 두고, 다시 누르면 수정으로 처리합니다.
취소 후 다시 요청하면 최근 90일 집계에 새 요청으로 잡히도록 생성 시각을
지금으로 바꿉니다.

알림 기능이 아직 없어 완료 문구에서 "알려드릴게요"를 뺍니다.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## 체크리스트

1. 제목에 prefix(`feat:`, `fix:`, `chore:` 등)가 없다.
2. 제목이 명사구로 끝난다. 예: `추가요 랭킹 화면` (O) / `추가요 랭킹 화면을 만들었습니다` (X)
3. 제목은 50자 안팎, 최대 72컬럼(한글 2컬럼).
4. 제목과 본문 사이에 빈 줄 하나.
5. 본문이 있다. 트레일러만 있는 커밋은 본문 없음이다.
6. 본문에 "왜 필요했는가"가 들어 있다. 파일·함수 목록 나열이 본문의 중심이면 다시 쓴다.
   - 자가 테스트: 이 메시지만 읽고 diff 없이 이유를 설명할 수 있는가?
7. 여러 방법 중 하나를 골랐다면 왜 골랐는지 한 문장 이상.
8. 본문은 현재형 존댓말(합니다체). 반말·과거형(이번 변경 서술에)은 쓰지 않는다.
9. 본문 각 줄이 72컬럼 이내이고, 문장이 끝나면 줄을 바꾼다.
10. 코드 식별자·파일명·명령은 백틱으로 감싼다.
11. `@`로 시작하는 단어가 날것으로 없다(GitHub 멘션이 된다).
12. 마지막 줄이 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`이다. 시스템이 다른 트레일러를 알려 주면 그것을 따른다.

## 메시지는 파일로 넘긴다

여러 줄 메시지는 임시 파일에 쓴 뒤 `git commit -F <파일>`로 넘긴다.
heredoc을 한 명령에 여러 개 이어 붙이면 셸이 경계를 잘못 읽어 다른 본문이 커밋 메시지로 들어갈 수 있다.

## 이력 수정은 매번 승인

`--amend`, `reset`, `rebase`, `push --force`는 매번 사용자 승인을 받는다. 실수를 고치려는 경우도 같다.
