코드 변경 뒤 `app/`이 배포 가능한 상태인지 확인한다. "확인했다"의 기준을 이 스킬 하나로 통일한다.

## 절차

### 1. 기본 검사

```bash
cd app && pnpm check
```

`pnpm check`는 순서대로 실행한다. 하나라도 실패하면 거기서 멈춘다.

1. `tsc --noEmit` — 타입 오류 없음
2. `eslint` — 린트 통과 (계층 의존 방향 규칙 포함)
3. `next build` — 프로덕션 빌드 성공

### 2. DB를 건드렸으면

스키마·마이그레이션·`src/server`의 쿼리를 바꿨다면 추가로 확인한다.

```bash
cd app && pnpm db:check && pnpm db:generate
```

- `db:check`: 두 접속 주소 연결 성공
- `db:generate`: "No schema changes" — 스키마 코드와 마이그레이션이 어긋나지 않음

### 3. 화면을 바꿨으면

개발 서버(`pnpm dev --port 3100`)에서 바꾼 화면을 열고, 서버 로그에 아래가 없는지 본다.

- `unstable value ... while prerendering` (Cache Components 규칙 위반)
- `Error`, `⨯`

브라우저 확장 프로그램 때문에 생긴 하이드레이션 경고(`chrome-extension://`)는 무시한다.

## 보고 형식

```text
- 타입 검사 ✅ / 린트 ✅ / 빌드 ✅
- DB: 연결 ✅ / 스키마 차이 없음 ✅   (해당할 때)
- 화면: /song/... 로그 오류 없음 ✅   (해당할 때)
```

실패하면 실패한 항목과 오류 요점을 보고하고, 고칠 방향을 제시한다. 지시 없이 고치기 시작하지 않는다. 단, 이번 작업에서 생긴 명백한 오류(타입 누락 등)는 고치고 다시 돌린다.

## 언제 돌리나 — 마지막 편집 뒤

- 검사를 통과한 뒤 코드를 한 줄이라도 고쳤으면 그 결과는 무효다. 다시 돌린다.
- 커밋 직전, PR 직전에 `git status`로 검사 뒤 편집이 없었는지 확인한다. 기억으로 판단하지 않는다.
- 자동 테스트(Vitest 등)를 도입하면 `pnpm check`에 넣고 이 파일을 고친다.
